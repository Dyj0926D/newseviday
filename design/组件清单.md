## 1. 组件策略

NewsEviday 的组件体系服务于三个目标：提高情报阅读效率、让 AI 结论可以回到证据、让招聘方快速理解产品和技术决策。

实现时遵守以下边界：

1. 先复用基础组件，再组合业务组件，不为单一页面创建只有外观差异的新组件。
2. 紫色只表达品牌、选中、引用和主要操作；成功、警告、错误使用各自的语义色。
3. 卡片依靠背景、细边框和间距建立层级，阴影只用于浮层、抽屉和确有悬浮关系的对象。
4. 组件必须覆盖正常、加载、空、错误、不可用或暂停等适用状态。
5. 图标统一使用同一套线性图标，默认 1.5px—2px 视觉笔画；不使用 emoji 充当界面图标。
6. 桌面和移动端复用同一个组件及 DOM 语义，通过布局属性重排；不维护两套业务组件。
7. 首版只做浅色主题。深色主题保留 token 扩展能力，不进入 MVP 验收。

优先级定义：

- `P0`：八个公开页面首版必须实现。
- `P1`：体验增强，可在静态产品完成后补充。
- `P2`：增强版能力，MVP 不实现。

优先级表示用户体验和状态是否必须覆盖，不代表每一行都要建立独立 Vue 文件。下方 80 个条目是设计与验收契约，MVP 的实际导出组件数量固定在 32 个以内：

| 实现层 | 数量上限 | 实现规则 |
|---|---:|---|
| 共用基础组件 | 16 | Header、容器、按钮、表单、筛选、Drawer、Disclosure、状态反馈等；优先组合成熟的 Vue headless primitive |
| 业务复合组件 | 16 | 情报条目、证据、RAG 工作区、简报、画像、Eval、状态和产品叙事等 |
| 页面内部片段 | 不单独计数 | 只在一个页面使用的标题行、元数据行或说明块先保留在页面/复合组件内部 |

组件提取门槛：同一结构被两个页面复用，或拥有独立状态、键盘交互、测试边界时，才提升为公共组件。`SourceMark`、`TranslationStatus`、`EvidenceItem`、`TraceStep` 等细粒度条目在首版可以作为父组件的 slot、render helper 或内部子组件，不强制导出。

## 9. 共用状态契约

每个数据组件通过统一属性接收状态，页面不得自行发明难以复用的状态表现。

```ts
type AsyncState =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; updatedAt?: string; isStale?: boolean }
  | { status: 'empty'; reason?: string }
  | { status: 'error'; code?: string; retryable: boolean };

type CapabilityState =
  | 'available'
  | 'saving-mode'
  | 'static-only'
  | 'rate-limited'
  | 'budget-paused';
```

统一约束：

- `isStale=true` 时保留往期内容，并在模块上方使用 warning 型 `InlineNotice` 标明最后更新时间。
- `error` 只替换失败模块，已经成功的内容继续展示。
- AI 能力暂停时，静态信息仍可阅读；相关按钮进入禁用态并解释原因和恢复方式。
- Skeleton 只在首次加载或结构未知时出现，后台刷新不清空已有内容。
- 空状态不能与错误状态共用同一文案和图标。

## 10. 实现与验收约束

1. Vue 组件使用 `PascalCase`；业务组件按本文件命名，避免同义重复。
2. 使用 Design Tokens，不在组件内散落新的 HEX、阴影、圆角和断点数值。
3. 组件文档至少提供 default、hover/focus、disabled、loading、empty/error 等适用示例。
4. 可交互元素都可用键盘访问，焦点顺序与视觉阅读顺序一致。
5. 触控目标不小于 44 × 44px；正文和关键控件满足 WCAG AA 对比度。
6. 页面在 360、390、768、1024、1280、1440px 六个验收宽度下无水平溢出。
7. 组件内容使用真实字段或明确标注的 demo fixture；不在生产页面生成随机数字和伪造指标。
8. 首版组件完成标准为“页面可用 + 状态完整 + 响应式可用”，不以组件数量作为完成指标。
9. P2 工程阶段建立组件台账；公共组件超过 32 个时必须先合并重复职责，再评估是否增加预算。

## 11. 暂不进入 MVP 的组件

- 用户账号、通知中心、收藏夹、团队协作和评论组件。
- 可视化运营控制台的复杂数据表、角色权限和审批组件。
- 自定义 Dashboard、拖拽布局和完整图表组件库。
- 深色主题切换器。
- 原生 App 导航和系统组件。

这些能力只有在 PRD 范围升级后再进入组件清单，避免 DEMO 演变为长期维护的大型平台。
