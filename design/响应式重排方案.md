| 关联文档 | [视觉设计基准](./视觉设计基准.md) · [Design Tokens](./设计令牌-Design-Tokens.md) · [组件清单](./组件清单.md) |

## 1. 目标与原则

响应式设计维持同一套品牌语言和内容层级。尺寸变化时调整列数、排列顺序、控件形态和信息密度，不把手机端做成另一套产品。

固定原则：

1. 首屏保留大标题和雾紫画布。标题只在用户向下滚动后进入紧凑状态，不因使用手机就预先删除。
2. 内容顺序按“结论 → 解释 → 证据 → 高级 Trace”排列。窄屏优先纵向重排，不通过缩小字号硬塞多列。
3. 同一页面只保留一个主要动作。次级动作进入更多菜单、Disclosure 或 Drawer。
4. 文章、问答和简报在手机上先展示正文，再展示证据；引用随时可打开证据 Drawer。
5. 筛选条件、问答范围和页面模式必须可见，不能因折叠而让用户不知道当前状态。
6. 不使用固定 `100vh` 锁定移动端页面；全屏浮层使用 `100dvh` 和安全区变量。
7. 所有触控目标不小于 44 × 44px，横向滚动区域显示截断提示或边缘渐隐。
8. DOM 顺序以移动端阅读顺序为基准，桌面双栏仅通过 CSS Grid 改变视觉位置。

## 2. 断点与容器

断点表示内容需要改变布局的时刻，不代表特定设备型号。

| 档位 | CSS 范围 | 典型场景 | 页面边距 | 主要布局 |
|---|---:|---|---:|---|
| 窄屏手机 | `< 640px` | 360/390px 手机 | 16px | 单列；筛选和标签可横向滚动 |
| 大屏手机 | `640—767px` | 横屏或大手机 | 20px | 单列；局部可用双列小指标 |
| 平板 | `768—1023px` | 竖屏平板、小窗口 | 24px | 单列为主；次要内容折叠；局部 2 列 |
| 紧凑桌面 | `1024—1199px` | 11—13 英寸窗口 | 28px | 可使用 7:5 双栏；导航收紧 |
| 标准桌面 | `1200—1439px` | 常见 PC | 32px | 8:4、9:3 或 42:58 双栏 |
| 宽屏桌面 | `≥ 1440px` | 大屏 PC | 32px | 页面最大 1440px，正文不继续拉宽 |

对应 Design Tokens：

```css
--ne-breakpoint-sm: 40rem;   /* 640px */
--ne-breakpoint-md: 48rem;   /* 768px */
--ne-breakpoint-lg: 64rem;   /* 1024px */
--ne-breakpoint-xl: 75rem;   /* 1200px */
--ne-breakpoint-2xl: 90rem;  /* 1440px */
```

容器规则：

- 全站大画布和首页信息流最大宽度 1440px。
- 一般页面内容最大宽度 1200px。
- 文章正文、回答正文等连续阅读区域最大宽度 720px。
- 宽度大于 1440px 后增加两侧留白，不继续放大文字和卡片。
- 断点数值只在布局样式或统一 composable 中引用，组件内部不新增私有断点。

## 3. 全局框架重排

### 3.1 顶部导航

| 宽度 | 布局 |
|---|---|
| `≥1200px` | Logo、情报流、趋势简报、情报问答、产品介绍完整展示；搜索和画像入口位于右侧。Header 高 64px。 |
| `1024—1199px` | 保留 Logo 与三项高频导航；“产品介绍”等低频入口进入“更多”；搜索缩为图标入口。 |
| `<1024px` | Header 高 56px，只展示 Logo、搜索图标和菜单按钮；导航从左侧 Drawer 打开，画像、Eval、状态和外部链接位于 Drawer 下半区。 |

滚动行为：

- 初始 Header 与大画布同色，不覆盖主标题。
- 当 `PageIntro` 底部离开视口后，Header 使用实色 surface、1px 下边框并显示当前页面名称。
- Header 压缩只改变高度、背景和可见信息，不让页面在切换状态时上下跳动。
- `prefers-reduced-motion: reduce` 下直接切换状态，不播放位移或渐变动画。

### 3.2 大标题区

| 宽度 | 标题与内容 |
|---|---|
| `≥1200px` | 首页标题使用 52—68px，自左上展开；说明控制在 2 行；可在右侧放一项真实信号概览或产品预览。最小高度 496px。 |
| `768—1199px` | 标题 40—52px；说明最多 3 行；标题和概览上下排列，首屏仍保留完整品牌表达。 |
| `<768px` | 标题 34—44px；说明自然换行；主要动作紧随正文；不强制占满整屏，最小上下内边距 64px。 |

### 3.3 页面操作与筛选

- PC：主要筛选作为一行工具条；次级筛选可以进入 Popover。
- 平板：保留视图切换和 1—2 个关键筛选，其余进入 Drawer。
- 手机：视图切换单独占一行；筛选入口显示已选数量；高频 `FilterChip` 支持横向滚动。
- 横向滚动的 chip 列必须可通过键盘滚动，并保留右侧 16px 内容预览，提示仍有更多选项。
- 弹出式复杂筛选在手机上统一改为底部 Drawer，底部固定“重置”和“应用”按钮。

### 3.4 页脚

- `≥768px`：品牌说明占 1 列，产品与透明度链接占 2 列。
- `<768px`：品牌说明在上，链接按 2 列排列；小于 390px 时可单列。
- GitHub、PRD 等外链标明“新窗口打开”。

## 4. 首页 `/`

### 4.1 桌面布局

- 首屏采用约 `68% : 32%` 的非对称网格：左侧价值主张、搜索和视图切换，右侧 `SignalOverview`。
- 首屏之后进入内容区。标准桌面使用 `minmax(0, 1fr) 320px`：左侧信息流，右侧为今日主题、地区分布和运行模式。
- `IntelligenceLead` 占信息流全宽，后续使用紧凑 `IntelligenceRow`，避免连续大卡片降低浏览速度。

### 4.2 重排规则

| 宽度 | 重排结果 |
|---|---|
| `1024—1199px` | 首屏右侧概览缩为 2 × 2 指标；内容区改为单列，信号概览的详细部分移到信息流上方。 |
| `768—1023px` | 标题、搜索、视图切换、紧凑信号概览、筛选、重点情报、列表依次纵向排列。 |
| `<768px` | 搜索占满一行；`SegmentedControl` 占一行；筛选 chip 横向滚动；`IntelligenceLead` 去除非必要配图，保留标题、判断和证据动作。 |
| `<640px` | `IntelligenceRow` 元数据拆为两行：来源/地区/语言在上，时间/证据数在下；推荐原因独立一行且最多 2 行。 |

信息优先级：

1. 中文标题；
2. 核心判断；
3. 来源、地区和时间；
4. 推荐原因与证据数；
5. 低频标签和技术元数据。

低频标签在手机上进入详情页，不应通过极小字号保留全部信息。

## 5. 文章详情 `/article/:id`

### 5.1 桌面布局

- `≥1200px`：正文与证据采用 `minmax(0, 720px) minmax(280px, 360px)`，间距 48px。
- 证据栏在文章标题区结束后进入 sticky，顶部偏移为 Header 高度 + 24px。
- 主要阅读顺序为标题 → 核心判断 → 正文 → 关联内容；证据栏与正文引用双向定位。

### 5.2 重排规则

| 宽度 | 重排结果 |
|---|---|
| `1024—1199px` | 保留约 7:5 双栏；证据栏不再 sticky 到页面底部，避免短窗口内滚动冲突。 |
| `768—1023px` | 单列正文；正文后的证据先展示摘要和数量，通过 `Disclosure` 展开完整证据。 |
| `<768px` | 顶部只保留“查看原文”和“追问”两个高频动作；复制等动作进入更多菜单。点击正文引用后从底部打开 `EvidencePanel` Drawer。 |
| `<640px` | 面包屑收为“返回情报流”；正文 16px、行高 1.7；引用点击区至少 44px，原文链接另开标签页。 |

移动端 DOM 顺序固定为：文章标题 → 核心判断 → 正文 → 完整证据 → 关联内容。证据 Drawer 只是快捷入口，页面末尾仍保留可访问的完整证据。

## 6. 情报问答 `/ask`

### 6.1 桌面布局

- `≥1200px`：回答区 8 列，证据与 Trace 4 列。
- 输入区位于大标题下方，提交后缩为 sticky composer，但不覆盖回答正文。
- 证据栏显示引用列表；Trace 默认只显示检索范围、召回数、耗时和版本，高级步骤折叠。

### 6.2 重排规则

| 宽度 | 重排结果 |
|---|---|
| `1024—1199px` | 回答区和证据区约 7:5；Trace 移到回答下方。 |
| `768—1023px` | 单列：输入 → 生成阶段 → 回答 → 引用 → Trace；证据列表默认展开前 3 条。 |
| `<768px` | `QuestionComposer` 固定在页面流内，不使用永久底部输入框；提交后显示“返回问题”锚点。证据和 Trace 分别使用 Disclosure。 |
| `<640px` | 范围选择从 segmented control 改为 Select；示例问题纵向排列；回答引用编号保持行内可点击。 |

流式状态：

- 页面宽度变化不能清空当前回答或重新发起请求。
- 流式文本按语义块刷新，避免逐字动画造成布局抖动。
- “取消生成”始终与当前进度同区域展示。
- AI 暂停、限流、无证据和请求失败使用不同的 `InlineNotice`/`NoEvidenceState`，不合并为一个通用错误。

## 7. 趋势简报 `/brief`

### 7.1 桌面布局

- 头部展示覆盖时间、来源数和语料状态。
- 主体使用 `minmax(0, 1fr) 288px`：左侧趋势正文，右侧为观察清单和简报元数据。
- 每个 `TrendBlock` 保持“判断—变化—影响—证据—不确定性”的固定顺序。

### 7.2 重排规则

| 宽度 | 重排结果 |
|---|---|
| `1024—1199px` | 主体变为单列，观察清单移到趋势正文之后。 |
| `768—1023px` | 每个趋势块内的地区对比从左右双栏改为上下结构。 |
| `<768px` | 简报元数据折叠为两行；证据默认显示 2 条，其余展开；观察清单使用编号列表。 |
| `<640px` | 不展示横向大表和复杂图例；所有变化指标同时使用文字说明。 |

历史简报仍可完整访问。当前整理暂停时，在 Header 下展示历史快照提示，不遮挡正文。

## 8. 我的画像 `/profile`

### 8.1 桌面布局

- `≥1200px`：表单与结构化预览使用 6:6 双栏；预览在滚动时保持可见，但不超过视口高度。
- 表单按“基础信息—关注主题—目标—可选语义增强”分组，避免一次展示复杂权重矩阵。

### 8.2 重排规则

| 宽度 | 重排结果 |
|---|---|
| `1024—1199px` | 约 7:5 双栏；主题权重改为紧凑列表。 |
| `768—1023px` | 单列：隐私说明 → 表单 → 生成预览 → 编辑权重 → 保存/导出。 |
| `<768px` | 兴趣选择采用可换行 chip；语义增强结果逐项编辑；保存动作位于内容末尾并提供顶部状态，不固定遮挡页面。 |
| `<640px` | Slider 同时显示数值输入；导入和导出分为两个按钮；删除画像使用二次确认。 |

画像不是必填流程。首次访问首页不能弹出画像 Modal；只通过“定制我的关注”和推荐空状态进入。

## 9. Eval `/eval`

### 9.1 桌面布局

- 首行展示 Eval 版本、运行时间、策略、语料版本和 commit。
- 关键指标使用 4 列 `MetricSummary`；指标解释和失败案例使用 8:4 布局。
- 目标门槛与实际结果采用不同 label，不以颜色暗示未运行项目已经通过。

### 9.2 重排规则

| 宽度 | 重排结果 |
|---|---|
| `1024—1199px` | 指标 3 列；详情改为单列。 |
| `768—1023px` | 指标 2 列；版本元数据换行；失败案例使用 Disclosure。 |
| `<768px` | 指标 2 列或极窄时单列；不使用宽数据表，改为“指标名—结果—门槛—解释”的指标卡。 |
| `<640px` | p50/p95、Recall/MRR 等成对指标仍保持分组；完整版本信息通过展开查看。 |

图表如无真实时间序列则不展示。单次 Eval 使用数字和解释，不能生成模拟趋势线。

## 10. 数据状态 `/status`

### 10.1 桌面布局

- `StatusSummary` 展示最后确认时间、运行模式、内容、问答和站点状态。
- 来源健康状态按“海外、国内、论文/GitHub”等真实分组展示，不用一张超宽表。
- 已知问题位于状态列表之后，带影响范围和最后更新时间。

### 10.2 重排规则

| 宽度 | 重排结果 |
|---|---|
| `≥1024px` | 总览 4 列指标；来源组可使用 2 列。 |
| `768—1023px` | 总览 2 列；来源组单列。 |
| `<768px` | 每个来源为一行：名称、状态、最后成功时间；技术错误详情折叠。 |
| `<640px` | 长时间戳换为相对时间 + 可展开绝对时间；状态图标旁始终保留文字。 |

状态数据本身过期时，页面只能说“最后一次确认于……”，不得推断当前运行正常。

## 11. 产品介绍 `/product`

### 11.1 桌面布局

- 首屏采用约 `42% : 58%`：左侧产品定位、亮点和入口，右侧使用实际界面截图或页面预览。
- 研究闭环在桌面横向展示；能力边界、Python/AI 分工和架构使用不同分区，避免成为一张信息密度失控的大卡片。
- 架构信息从上至下保持“来源 → 处理 → 存储 → RAG/Eval → API → 前端”的阅读方向。

### 11.2 重排规则

| 宽度 | 重排结果 |
|---|---|
| `1024—1199px` | 首屏约 45:55；截图裁切只隐藏装饰留白，不裁掉产品核心内容。 |
| `768—1023px` | 首屏改为文案在上、产品预览在下；研究闭环保持 5 步横向，但允许容器滚动。 |
| `<768px` | 产品预览占满内容宽度；研究闭环改为纵向时间线；架构图改为分层列表。 |
| `<640px` | 主要动作纵向排列；GitHub、PRD、Eval、状态使用 2 列链接清单，不做三张等宽营销卡。 |

移动端架构不能只放一张缩小后无法阅读的 PC 图片。实现时使用语义化 HTML 分层重排；如同时提供图片，图片只作为概览并支持查看原图。

## 12. 浮层、键盘与安全区

### 12.1 Drawer 与 Modal

- 手机筛选和证据使用底部 Drawer；导航使用左侧 Drawer。
- Drawer 最大高度为 `min(88dvh, content-height)`，顶部保留拖动视觉提示但不依赖拖动才能关闭。
- 底部动作区使用 `padding-bottom: max(16px, env(safe-area-inset-bottom))`。
- 打开后焦点进入标题或首个控件；关闭后焦点回到触发器。
- 背景内容不可滚动，Esc、关闭按钮和遮罩均可关闭非破坏性 Drawer。

### 12.2 键盘和可访问性

- 视觉重排不改变语义阅读顺序。
- skip link 首次键盘聚焦时显示，可直接跳到主内容。
- Focus Ring 使用 `--ne-color-focus` 和 `--ne-shadow-focus`，不能被 `overflow: hidden` 裁切。
- 水平 chip 列、轮播式预览和代码块均可用键盘滚动。
- 图表、状态和趋势同时提供文字摘要。

## 13. 加载、空、错误和暂停状态

| 状态 | 桌面 | 移动端 |
|---|---|---|
| 首次加载 | 在目标模块内展示同结构 Skeleton，不遮挡全页 | Skeleton 高度缩短，保留页面标题和返回能力 |
| 后台刷新 | 继续展示旧内容，在模块标题显示刷新状态 | 同桌面，不将列表清空为 Skeleton |
| 空结果 | 保留筛选和搜索上下文，提供清除条件 | 动作纵向排列；明确当前筛选条件 |
| 局部失败 | 只替换失败模块，其他模块继续工作 | 错误说明紧贴模块，提供重试 |
| 历史快照 | 页面标题下展示最后更新时间 | 使用两行提示，不使用占满首屏的大警告块 |
| AI 暂停 | 静态内容正常，AI 按钮禁用并说明恢复条件 | 同桌面；按钮附近展示原因，避免点击后才提示 |
| 限流 | 显示剩余额度或重置时间 | 使用 inline notice，不使用阻断全页 Modal |

## 14. 内容长度与溢出

- 中文标题在信息流中桌面最多 2 行、手机最多 3 行；文章详情标题不截断。
- 来源名称允许省略，但保留 `title`/可访问全称；域名和 URL 使用 `overflow-wrap:anywhere`。
- 推荐原因最多 2 行；完整理由可在详情或 Tooltip/Disclosure 查看。
- 标签行不通过缩小字号容纳全部标签，多余项显示“+N”或移入筛选 Drawer。
- 表格只用于确实需要按列比较的数据。小于 768px 时切换为定义列表或指标卡，不要求用户横向拖动大表。
- 产品截图使用固定宽高比容器和 `object-fit: cover/contain` 的页面级规则；核心文字内容不能被裁切。

## 15. 动效规则

- 动效强度固定为 4/10，只用于状态反馈和层级变化。
- Header 压缩、Drawer、Disclosure、筛选选中使用 120—240ms。
- 首屏内容可做一次 240—360ms 的轻微上移和淡入；信息流不逐项长时间入场。
- 只动画 `transform` 和 `opacity`；高度折叠应避免触发布局抖动或使用浏览器原生 Disclosure。
- 流式回答不做字符跳动、发光或扫描动画。
- `prefers-reduced-motion: reduce` 时，所有非必要动画时长归零。

## 16. 验收矩阵

### 16.1 必测视口

| 类型 | 尺寸 | 重点 |
|---|---:|---|
| 小手机 | 360 × 800 | 标题换行、触控区、Drawer、安全区、无横向溢出 |
| 常见手机 | 390 × 844 | 信息流密度、问答和证据流程 |
| 平板 | 768 × 1024 | 单双栏切换、导航、指标布局 |
| 紧凑桌面 | 1024 × 768 | Header 收紧、7:5 布局和短视口 sticky 行为 |
| 标准桌面 | 1280 × 800 | 四张 reference 的总体比例和信息层级 |
| 宽屏桌面 | 1440 × 900 | 最大宽度、两侧留白和阅读宽度 |

### 16.2 页面验收

每个公开页面必须在上述六个视口完成：

- 无页面级水平滚动；代码块和明确标识的 chip 容器可局部横向滚动。
- Header、返回、主要动作和当前模式可识别。
- 标题、正文、证据和状态的视觉层级保持一致。
- 主要流程不依赖 hover，键盘和触屏都可完成。
- 页面缩放至 200% 时关键功能仍可使用。
- 真实中英文混排、长来源名、空数据和接口错误均不破版。
- 从桌面切换到移动宽度时，不丢失搜索、筛选、画像或正在生成的回答状态。

## 17. 实施顺序

1. 先实现全局容器、Header、PageIntro、Drawer 和通用状态。
2. 以首页信息流验证 360—1440px 的断点与密度。
3. 以文章详情验证正文、引用和证据在双栏/单栏之间切换。
4. 以情报问答验证流式状态、取消和 Trace 重排。
5. 补齐趋势、画像、Eval、状态和产品介绍页。
6. 使用六个固定视口做视觉回归，并增加中文长标题、英文长词、无证据、AI 暂停等边界 fixture。

以上顺序只固定前端实施方法，不改变 PRD 的功能优先级。
