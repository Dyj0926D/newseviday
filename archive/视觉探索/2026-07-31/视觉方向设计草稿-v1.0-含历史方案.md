# NewsEviday 视觉方向设计草稿

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 日期 | 2026-07-31 |
| 状态 | 主视觉方向已确认，4 张 PC 页面 reference 已生成 |
| 适用页面 | 首页、文章详情、问答、画像、Eval、产品介绍页 |

## 1. 设计解读

**设计解读：这是一个面向 AI / 数据产品经理和招聘者的情报产品与作品集。视觉语言调整为 Linear 式现代工具感与国际科技编辑排版结合，使用灰白、浅紫和石墨色，强调留白、秩序、克制动效和高可读信息结构。**

项目属于 Greenfield。

设计参数：

| 参数 | 数值 | 原因 |
|---|---:|---|
| DESIGN_VARIANCE | 6 | 有品牌感和不对称节奏，同时保证信息流可读 |
| MOTION_INTENSITY | 4 | 用于状态反馈和轻量叙事，不做炫技滚动 |
| VISUAL_DENSITY | 6 | 情报产品需要较高信息密度，但不能像监控驾驶舱 |

设计技能主要用于产品介绍页和整体品牌表达。信息流、画像和运营页属于产品界面，优先保证可用性、状态完整和移动端效率。

## 2. 推荐方向

已确认最终方向：方案 C“云雾紫”的整体框架 + 方案 A“霁紫”的信息流组件。

原因：

- 顶部导航和大画布更简约、大气，适合公开作品集首页；
- 浅紫只承担品牌识别，不影响长标题和中文摘要阅读；
- 首页首屏可以同时表达产品定位、信息流和趋势能力；
- 方案 A 的列表密度更适合后续“为你推荐”和检索结果页；
- 首屏完整保留大标题和产品定位；页面向下滚动后再压缩为紧凑导航与筛选栏。

## 3. 第一轮三套视觉方向

### 方向 A：全球情报编辑部

定位：

像一家专门研究 AI 和数据产品的国际数字编辑部。页面以排版、信息层级、来源语言和证据关系为核心。

视觉关键词：

- 国际科技媒体；
- 编辑部版式；
- 冷静、可信；
- 高密度留白；
- 中文阅读友好；
- 单一深青绿色强调。

首页布局：

- 桌面端左侧为品牌和一级导航；
- 中间是主信息流；
- 右侧为 7 日趋势、数据新鲜度和运行状态；
- 首条重点信息使用较大标题和横向信息结构；
- 普通信息使用分组列表，减少满屏卡片；
- 海外来源、原始语言和翻译状态使用简洁文字标识；
- 推荐原因位于摘要下方，不覆盖标题。

产品介绍页：

- 使用不对称双栏首屏；
- 左侧为一句产品价值；
- 右侧使用真实产品视觉稿或生成的产品情境图；
- 中段通过“海外原始信息到中文证据”的纵向叙事展示核心能力；
- 架构和 Eval 使用浅色技术图表；
- 结尾只保留一个主要 CTA：体验信息流。

适合：

- 首页；
- 文章详情；
- 产品介绍页；
- 7 日趋势简报。

风险：

- 排版不好会像普通新闻站；
- 需要真实截图和信息样本支撑；
- 中文与英文混排需要提前测试。

### 方向 B：证据档案馆

定位：

像一个整理 AI 产品证据、版本和来源的数字研究档案馆。强调来源、版本、引用和可追溯性。

视觉关键词：

- 档案；
- 研究；
- 证据编号；
- 纸张与数据库结合；
- 稳重；
- 低饱和墨绿。

首页布局：

- 使用较强的纵向时间线；
- 信息以事件组展示；
- 每条事件强调来源数量、国内外分布和更新时间；
- 证据、引用和评测使用一致的视觉符号；
- 文章详情像研究卡片，原文与中文摘要并列。

产品介绍页：

- 首屏展示“从原始信号到可信判断”的核心句；
- 用一组真实证据卡表现产品能力；
- 技术架构使用档案盒式模块，但避免过度卡片化；
- Eval 部分像研究报告摘要。

适合：

- 文章详情；
- RAG 引用；
- Eval；
- 数据状态页。

风险：

- 容易显得严肃、偏研究工具；
- 首页新鲜感弱于方向 A；
- 手机端需要减少元数据。

### 方向 C：信号观测台

定位：

像一个观察 AI、数据和开源趋势的信号系统。强调新动态、趋势变化和数据状态。

视觉关键词：

- 信号；
- 网络；
- 轻量深色；
- 数据观察；
- 细线与微动效；
- 青绿色单一强调。

首页布局：

- 右侧趋势面板更突出；
- 国内外信息使用双轨来源视图；
- 新信息、历史快照和 RAG 状态具有明确语义状态；
- 允许少量实时感动效，例如数据更新时间和流式回答。

产品介绍页：

- 使用真实全球来源分布图或生成的抽象信息网络图；
- 通过流动路径表现采集、理解、检索和验证；
- 架构图与产品能力更像一个连续系统。

适合：

- 趋势简报；
- 状态页；
- RAG 问答；
- 架构展示。

风险：

- 深色科技视觉容易接近常见 AI 模板；
- 长文本和中文阅读体验稍弱；
- 动效和移动端性能成本较高。

## 5. 第一轮方向 A 的设计系统草稿

### 5.1 主题

默认跟随系统主题。单个页面保持一个主题，不在页面中段突然翻转明暗。

亮色为主要展示模式：

| Token | 草稿值 | 用途 |
|---|---|---|
| `--bg` | `#F4F6F3` | 页面背景 |
| `--surface` | `#FFFFFF` | 主要内容面 |
| `--surface-muted` | `#EAEFEC` | 次级区域 |
| `--text` | `#17201C` | 主文本 |
| `--text-muted` | `#68756E` | 次文本 |
| `--border` | `#D5DDD8` | 分隔与边框 |
| `--accent` | `#2A6F5E` | 唯一品牌强调色 |
| `--accent-hover` | `#225C4E` | 交互状态 |
| `--danger` | `#A1473D` | 真实错误状态 |

深色草稿：

| Token | 草稿值 |
|---|---|
| `--bg` | `#111714` |
| `--surface` | `#18201C` |
| `--surface-muted` | `#202A25` |
| `--text` | `#E8EEE9` |
| `--text-muted` | `#A7B3AC` |
| `--border` | `#303B35` |
| `--accent` | `#58B39B` |

### 5.2 字体

- 中文正文：系统中文无衬线字体栈。
- 英文和数字：Geist / Geist Mono，自托管。
- 正文不使用装饰性衬线字体。
- 数字指标、时间和模型版本使用等宽字体。
- 标题通过字重和留白建立层级，不使用过大的 H1。

字体栈建议：

```css
font-family:
  "Geist",
  "PingFang SC",
  "Microsoft YaHei",
  "Noto Sans CJK SC",
  sans-serif;
```

### 5.3 形状

- 信息容器：12px 圆角；
- 输入框和按钮：8px 圆角；
- 标签与筛选：允许使用全圆角；
- 标签只用于分类和筛选，不将普通正文包装成胶囊；
- 阴影很少使用，优先用间距、背景和单侧分隔线。

### 5.4 图标

- 使用 Phosphor Icons；
- 全站使用同一图标家族；
- 默认 `strokeWidth` 为 1.5；
- 不手绘装饰 SVG；
- 国内/海外、来源、时间和引用优先用文字，图标作为辅助。

### 5.5 动效

只保留以下动效：

- 页面和信息卡轻量淡入；
- 筛选切换的布局过渡；
- RAG 流式回答；
- 引用点击后的定位高亮；
- 画像确认后的排序变化；
- 按钮按压反馈；
- 状态变化提示。

不使用：

- 无限循环背景；
- 大面积视差；
- 横向滚动劫持；
- 自定义鼠标；
- 复杂 3D；
- 全页 GSAP 动效。

所有动效遵守 `prefers-reduced-motion`。

## 6. 页面视觉说明

### 6.1 首页

首屏必须在一个视口内展示：

- NewsEviday 品牌；
- 一句话定位；
- 全部动态 / 为你推荐；
- 分类与国内外筛选；
- 至少一条真实或明确标记的示例信息。

桌面：

- 12 列网格；
- 左导航约 2 列；
- 信息流约 7 列；
- 趋势和状态约 3 列；
- 顶部导航高度 64-72px；
- 不使用三张等宽功能卡作为主要版式。

手机：

- 单列信息流；
- 顶部为品牌、搜索和设置；
- 底部导航保留首页、简报、问答、画像；
- 筛选使用底部抽屉；
- 次要元数据折叠；
- 推荐原因最多一行。

### 6.2 文章详情

- 中文标题优先；
- 原始标题紧随其后；
- 来源、语言和时间放在同一元数据区；
- 关键事实使用纵向结构；
- 引用与证据使用可展开列表；
- 当前文章问答固定在正文后，不使用悬浮聊天气泡；
- 手机端来源与证据使用抽屉或折叠区。

### 6.3 RAG 问答

- 输入区像搜索和研究工具；
- 回答区突出正文可读性；
- 引用紧跟事实句；
- 证据面板显示来源、日期、语言和片段；
- 加载状态使用与正文形状一致的 skeleton；
- 暂停状态显示归档说明和缓存示例。

### 6.4 Eval

- 首屏先说明“这些指标代表什么”；
- 目标值和实际值使用不同标签；
- 核心指标使用 4-6 个指标块；
- 详细结果使用可折叠表；
- 失败案例比漂亮图表更重要；
- 手机端指标块纵向排列；
- 不使用装饰性进度条。

### 6.5 画像页

- 先说明画像可选和隐私规则；
- 表单标签放在输入框上方；
- AI 增强前显示第三方模型处理提示；
- 画像预览使用可编辑主题与权重；
- 用户可以跳过、清除和切回通用流；
- 错误信息直接显示在对应输入附近。

### 6.6 产品介绍页

页面性质：

产品介绍页兼具 Landing Page 和作品集 Case Study。设计品味规则重点作用于该页面。

首屏：

- 左侧品牌、核心价值和“体验信息流”；
- 右侧使用真实产品截图或 Image 2 生成的界面情境图；
- 标题最多两行；
- 副文案控制在 20 个中文字左右；
- 首屏不展示版本号、虚构用户数和虚构客户。

推荐页面叙事：

1. 产品解决的问题；
2. 海外信息到中文证据；
3. 产品闭环；
4. 可选画像和推荐；
5. Python 与 AI 的能力分工；
6. RAG 和 Trace；
7. Eval 和失败案例；
8. 成本、安全和暂停模式；
9. GitHub、PRD 和真实产品入口。

布局要求：

- 至少使用四种不同布局结构；
- 相邻部分不连续使用三次图文左右交替；
- 页面最多一个 marquee，默认不使用；
- 重要架构使用真实生成图或正式 Mermaid 渲染；
- 不使用 div 拼出的假产品截图；
- 最终开发后替换为真实产品截图。

## 7. Image 2 生成提示词草稿

### 7.1 方向 A

> 为 NewsEviday 设计一张 1440×900 的高保真桌面网页视觉稿。产品是面向 AI 和数据产品经理的海内外技术情报网站，突出海外英文信息的中文整理、证据引用、个性化推荐和 7 日趋势。采用国际科技编辑部风格，浅冷灰绿色背景，深墨色文字，单一低饱和深青绿色强调。左侧导航，中央信息流，右侧趋势与状态。信息密度较高，排版克制，中文长标题清晰，海外来源和原文语言可见。避免紫色 AI 渐变、玻璃拟态、三张等宽功能卡、虚构数据、悬浮聊天气泡和复杂霓虹效果。

### 7.3 方向 C

> 为 NewsEviday 设计一张 1440×900 的高保真桌面网页视觉稿。风格是克制的 AI 与数据趋势信号观测台，深色中性背景，单一青绿色强调，突出国内外双轨情报、趋势变化、RAG 状态和数据新鲜度。保持长文本可读性和产品经理视角，动效只通过视觉暗示表达。避免蓝紫霓虹、科幻地球、过度发光、复杂驾驶舱和游戏化界面。

## 9. 第二轮：Linear 紫色方向

用户反馈：整体倾向 Linear 风格，要求简约、现代、大气，并尝试偏紫色、浅紫色系。

共同原则：

- 借鉴 Linear 的秩序、留白、精确控件和克制层次，不复刻其页面；
- 主背景以灰白或雾紫为主，紫色承担选中态、焦点和关键动作；
- 保留 NewsEviday 的跨语言、证据、推荐理由和趋势信息；
- 避免大面积炫光、玻璃拟态、蓝紫霓虹和常见 AI 落地页模板；
- 正式页面使用 Vue 组件和真实数据实现，视觉稿不直接作为网页背景。

### 9.1 方案 A：霁紫

- 浅色工具型工作台；
- 左侧导航、中央信息流、右侧趋势；
- 信息效率最高，适合作为登录后的默认工作界面；
- 风险是结构接近常见 SaaS 后台，需要通过品牌排版和证据链强化差异。

### 9.2 方案 B：暮紫

- 深紫侧栏与浅色阅读区形成强分区；
- 品牌识别最明显，层次稳定；
- 适合长时间使用和复杂功能扩展；
- 风险是深色侧栏略有管理后台感。

### 9.3 方案 C：云雾紫

- 顶部导航与大画布结构；
- 留白最好，视觉最现代、大气；
- 适合公开主站、作品集展示和产品介绍；
- 风险是首屏标题区占用较多空间，需要在前端实现时压缩高度。

视觉稿目录：`design/视觉稿/Linear紫色方向/`。

## 10. 最终视觉方向：云雾大画布 + 霁紫信息流

### 10.1 一句话定义

使用云雾紫的大画布承载产品定位和品牌气质，使用霁紫的高效列表承载持续阅读与研究动作。页面初始状态舒展、安静；进入内容后逐步收紧，形成从“看见方向”到“处理信息”的节奏变化。

### 10.2 视觉气质

| 维度 | 要求 |
|---|---|
| 品牌感受 | 简约、现代、大气、冷静、可信 |
| 产品属性 | 国际情报产品、AI 研究工具、个人作品集 |
| 主色倾向 | 灰白、雾紫、浅紫、石墨黑 |
| 紫色用途 | 品牌焦点、选中态、推荐原因、关键动作 |
| 信息密度 | 首屏低到中密度；进入信息流后中高密度 |
| 视觉层次 | 依赖留白、排版、细边框和明度差，不依赖重阴影 |
| 技术可实现性 | Vue、CSS Variables、Sticky、IntersectionObserver |

风格借鉴 Linear 对间距、层级、控件和状态的处理方式，不复刻其品牌、页面结构或视觉资产。

### 10.3 页面骨架

桌面端统一使用：

1. 顶部全局导航；
2. 页面级大标题区；
3. 主题筛选和页面动作；
4. 主要内容区；
5. 右侧上下文面板，仅在有明确价值时出现；
6. 页面底部的补充内容或下一层入口。

首页使用 68/32 的信息流与信号面板。文章详情使用正文与证据面板。情报问答使用回答与引用面板。产品介绍页使用宽幅叙事区，不沿用后台三栏。

### 10.4 首屏与滚动行为

首页首次进入时完整保留大标题区域，不压缩：

- 眉题：`DAILY INTELLIGENCE · 今日更新`
- 主标题：`发现变化，看见脉络`
- 副标题：`海内外 AI 与数据情报，经过翻译、整理与证据关联`
- 辅助动作：`定制我的关注`

滚动行为：

1. 初始状态展示完整标题、说明和主题筛选；
2. 用户向下滚动进入信息流后，标题区自然离开视口；
3. 顶部导航缩为 56-64px 的粘性工具栏；
4. 当前页面名称、搜索和主题筛选进入紧凑工具栏；
5. 向上滚动时恢复必要的上下文，但不强制把完整大标题拉回；
6. 动画控制在 180-240ms，使用位移、透明度和背景模糊的轻量变化；
7. `prefers-reduced-motion` 开启时取消缩放和位移动画；
8. 压缩过程不改变内容宽度，不产生列表跳动。

手机端保留同一叙事顺序。首屏标题允许完整显示，筛选横向滚动；进入内容后只保留品牌、搜索和当前主题。

### 10.5 信息流组件

采用方案 A 的列表效率，减少大面积独立卡片：

- 第一条为重点情报，允许较大标题、摘要和推荐原因；
- 后续条目使用细分隔线形成连续列表；
- 标题最多两行，摘要在桌面端最多两行；
- 来源、地区、翻译状态、时间和证据数位于同一元数据行；
- 推荐原因使用浅紫底色或紫色文字，不覆盖正文；
- 收藏、查看证据和更多操作固定在条目右侧；
- 仅重点情报使用柔和浅紫描边；
- 图标只用于帮助扫读，不给每条内容配置装饰图片。

信息条目示例：

- 标题：`Data Agent 正在进入企业数据平台`
- 摘要：`多家厂商开始把检索、语义理解与任务执行整合为统一的数据工作入口。`
- 元数据：`The New Stack · 海外 · 已翻译 · 2 小时前 · 12 条证据`
- 推荐原因：`与你关注的 Data Agent、企业数据平台高度相关`
- 动作：`查看证据`、`收藏`

### 10.7 字体与形状

- 中文优先使用系统黑体栈，后续可评估 `MiSans` 或 `Noto Sans SC`；
- 英文与数字使用 `Inter` 风格的现代无衬线字体；
- 大标题字重 600-700，正文 400-500；
- 正文行高 1.6 左右，信息流标题行高 1.35 左右；
- 页面级容器圆角 14-18px；
- 普通按钮和输入框圆角 8-10px；
- 标签可使用胶囊形，但不把所有按钮做成胶囊；
- 阴影只用于浮层，页面结构主要依靠边框和明度差。
