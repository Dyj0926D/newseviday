# NewsEviday 内容评分与 Key Signal 指标体系

> 版本：v2.0
> 更新时间：2026-08-14
> 适用范围：每日内容筛选、中文整理优先级、首页 Key Signal、内容质量评测

## 1. 设计目标

指标体系需要同时回答三个问题：

1. 这篇内容是否适合进入普通情报库存；
2. 这是否是一个会改变产品、技术、合规或成本判断的变化事件；
3. 现有证据是否足以把它放到首页 Key Signal。

三个问题分层计算。用户兴趣匹配只影响普通排序和用户价值，不再拥有否决重大事件的权力。

## 2. 三层判断结构

| 层级 | 作用 | 主要输出 | 是否需要中文 |
| --- | --- | --- | --- |
| 变化事件识别 | 判断是否发生了具体变化 | `eventTypes`、事件显著性、决策影响、采用扩散 | 否 |
| 普通内容评分 | 决定入库和普通信息流相对价值 | `contentScore`、11 项分值、入选理由 | 否 |
| Key Signal 门禁 | 判断是否可以进入首页重点位 | 专用分数、资格、失败原因 | 是 |

高显著性外文事件会优先获得有限的中文整理名额。媒体或博主信息即使暂时不能成为 Key Signal，也可以先进入“高显著性待核验”路径。

## 3. 变化事件类型

| 类型 | 典型变化 | 强证据要求 | 常见误判保护 |
| --- | --- | --- | --- |
| 政策与监管 | 法规出台、生效、强制要求、禁令、执法 | 政策主体 + 实质动作；优先官方一手来源 | 只谈政策背景不算变化 |
| 产品发布 | 新模型、新产品、新平台正式可用 | 发布动作 + 产品对象；正式可用、广泛开放会加分 | 小功能换皮不等于产品发布 |
| 能力更新 | API、兼容性、价格、核心能力变化 | 更新动作 + 产品对象；决策条件变化会加分 | 普通教程和营销描述不加分 |
| 采用扩散 | 用户、客户、下载、部署、市场份额增长 | 采用描述 + 数量、增速或规模证据 | “很流行”等主观描述不算采用证据 |
| 技术突破 | 有对照的性能、成本、能力提升 | 新方法 + 对照 + 量化或评测；论文需可泛化 | 结构完整但窄领域的论文不自动入选 |
| 市场结构 | 收购、合并、融资、战略合作 | 明确交易或合作事实；金额和影响范围会加分 | 普通合作宣传不自动成为重点情报 |
| 安全与风险 | 严重故障、漏洞、泄露、召回、调查 | 明确事件 + 影响或处置证据 | 安全科普文章不算风险事件 |

规则会识别简单否定语义。“没有用户数据”“未发布新产品”等表述不会被当成正向事件证据。

## 4. 普通内容总分

| 维度 | 权重 | 说明 |
| --- | ---: | --- |
| 目标主题相关性 | 20% | 与默认画像和项目关注方向的匹配程度 |
| 事件显著性 | 15% | 是否发生明确且幅度较大的变化 |
| 决策影响 | 8% | 是否会改变产品、技术、合规、迁移或成本选择 |
| 采用扩散 | 5% | 是否存在可观察的用户、客户、部署或市场增长 |
| 技术改进 | 8% | 是否有新方法、量化提升、评测或可复现产物 |
| 工程适用性 | 8% | 是否涉及部署、接口、成本、可靠性和生产工作流 |
| 技术普适性 | 6% | 是否适用于多个模型、任务、领域或组织 |
| 产品与行业影响 | 10% | 对产品能力、行业结构和企业使用的影响 |
| 新鲜度 | 10% | 相对实际采集时间计算，七天线性衰减 |
| 证据成熟度 | 7% | 来源层级、量化数据、评测、产物和正文完整性 |
| 内容完整度 | 3% | 是否有足够的来源摘要；论文不会因摘要完整获得额外优势 |

技术改进、工程适用性和技术普适性合计 22%，继续保持在 20%–30% 的产品约束内。

## 5. Key Signal 专用评分与门禁

Key Signal 专用分由以下部分组成：

- 用户价值 20%；
- 变化幅度 30%；
- 可行动性 20%；
- 技术普适性 10%；
- 新鲜度 10%；
- 证据成熟度 10%。

必须同时满足：

1. 已有中文标题与中文导读；
2. 事件显著性不低于 0.70；
3. 决策影响、采用扩散或技术改进至少一项不低于 0.60；
4. 与 AI、产品或技术决策范围存在明确联系；
5. 来源证据不少于 120 字，证据成熟度不低于 0.50；
6. 专用分通常不低于 0.65；7 天内且具有一手证据、事件显著性不低于 0.85、决策或采用影响不低于 0.75 的重大事件，可在专用分不低于 0.55 时继续进入观察窗；
7. 媒体和个人观点不能单独成为 Key Signal；
8. 学术内容还需具备高相关、可泛化且有对照的技术突破证据。
9. 首页实时 Key Signal 的发布时间不得超过 7 天；较旧内容仍保留在情报流和知识库中。

Key Signal 不再依赖 `contentScore >= 0.75`，也不再要求个性化相关性必须达到 0.65。重大政策、产品发布和广泛采用等事件可以跨过较窄的兴趣主题边界。

## 6. 中文整理与成本控制

有限模型名额按以下顺序分配：

1. 只缺中文即可成为 Key Signal 的内容；
2. 事件显著性不低于 0.70、证据达到最低要求的内容；
3. 3 天内、总分不低于 0.42、主题相关度不低于 0.60，且工程、技术或产品价值至少一项不低于 0.55 的新内容；
4. 普通内容总分和主题相关性同时达到原有付费门槛的内容；
5. 首页高位外文内容；
6. 其余内容不调用模型。

专业媒体的高显著性事件允许先翻译以便人工核验，但仍受“不能单一二手来源成为 Key Signal”的发布门禁约束。

## 7. Eval Harness

固定数据集：`pipeline/eval/key-signal-gold-v1.json`。

当前 v1 数据集包含 16 个黄金样例：7 个可发布 Key Signal、1 个高显著性待核验事件和 8 个反例。覆盖模型/API 更新、政策、产品发布、采用增长、技术突破、市场变化、风险事件、营销小更新、窄领域论文、媒体单一来源、主观流行判断、普通教程、检索 Recall 指标、语境性 adoption 描述、ROI 表述和过期工程更新。

事件识别同时采用三项精度约束：英文关键词按完整词匹配，避免把 `designed` 当成 `signed`；采用扩散必须绑定用户、客户、下载、部署、使用增长或市场份额等规模证据；政策、产品发布、能力更新、市场结构和风险事件优先要求标题或导语出现明确变化。

每次日更和 CI 运行以下指标：

- Key Signal 资格 Precision、Recall、F1；
- 高显著性候选 Precision、Recall、F1；
- 事件类型完全匹配准确率；
- 失败样例列表。

当前工程门禁要求黄金集无失败样例。16 个样例只能证明规则满足已定义边界，不能替代真实新闻的持续人工抽检。后续每次出现误判或漏判，都应先加入黄金集，再调整规则。

## 8. 已知边界

- 事件识别仍是确定性文本规则，暂不调用模型做事件分类；
- 跨来源事件聚合目前使用标题词项发现候选，不会自动合并文章；
- “某功能开始流行”需要数量、增长、样本或多来源证据。只有主观热度时只作为线索；
- 媒体、博主和厂商自报的采用数据需要人工或跨来源复核；
- 事件类型、权重和门槛需要结合每日误判样例持续扩充 Eval Harness。
