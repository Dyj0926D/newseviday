# NewsEviday 运营开关操作手册

## 1. 结论

NewsEviday 不依赖 Codex 对话控制。当前采用 GitHub 与 Cloudflare 两层控制：

- GitHub 控制后台采集、文章整理、周报和自动发布；
- Cloudflare 控制访客可调用的在线 AI、RAG、限流和预算；
- 公开网站不设置 `/admin`，避免为 MVP 额外引入后台账号、权限和攻击面。

## 2. 常用入口

| 入口                                                                                          | 用途                                       |
| --------------------------------------------------------------------------------------------- | ------------------------------------------ |
| [GitHub Actions](https://github.com/Dyj0926D/newseviday/actions)                              | 查看任务、手动执行一次内容刷新或周报       |
| [GitHub Actions Variables](https://github.com/Dyj0926D/newseviday/settings/variables/actions) | 开关定时任务、调整调用上限和截止日期       |
| [GitHub Actions Secrets](https://github.com/Dyj0926D/newseviday/settings/secrets/actions)     | 管理 DeepSeek Key；不要把 Key 写入普通变量 |
| [Cloudflare Workers](https://dash.cloudflare.com/?to=/:account/workers-and-pages)             | 管理线上 Worker、环境变量、日志和部署      |

上述页面均使用 GitHub 或 Cloudflare 自身的账号认证，可以在其他电脑和手机浏览器中操作。

## 3. 后台内容开关

| 变量                                    | 建议值           | 作用                                 |
| --------------------------------------- | ---------------- | ------------------------------------ |
| `DAILY_REFRESH_ENABLED`                 | `false` / `true` | 每日采集与文章整理总开关             |
| `DAILY_REFRESH_END_DATE`                | `yyyy-MM-dd`     | 受控运行截止日期；开启日报时必须设置 |
| `DAILY_REFRESH_ALLOW_MODEL`             | `false` / `true` | 是否允许日报调用 DeepSeek            |
| `DAILY_REFRESH_MAX_MODEL_CALLS`         | `5`              | 每日基础调用额度                     |
| `DAILY_REFRESH_MAX_MODEL_CALLS_PER_RUN` | `10`             | 单次任务硬上限，包含结转额度         |
| `DAILY_REFRESH_AUTO_MERGE`              | `false` / `true` | 定时日报通过门禁后是否自动发布       |
| `WEEKLY_BRIEF_ENABLED`                  | `false` / `true` | 周报采集与生成总开关                 |
| `WEEKLY_REFRESH_AUTO_MERGE`             | `false` / `true` | 定时周报通过门禁后是否自动发布       |

修改变量后无需重新部署网站，下一次 GitHub 定时任务会读取新值。`workflow_dispatch` 手动任务不受定时总开关限制，执行前仍要检查 `allow_model`。

## 4. 本地快捷控制

在安装并登录 GitHub CLI 的设备上，可以在项目根目录运行：

```powershell
# 查看状态，不修改任何配置
.\scripts\ops-control.ps1 -Mode Status

# 归档：关闭日报、周报、模型许可和自动发布
.\scripts\ops-control.ps1 -Mode Archive

# 只保留每周趋势简报
.\scripts\ops-control.ps1 -Mode WeeklyOnly

# 开启一段最长 31 天的受控运行；默认不调用模型、不自动发布
.\scripts\ops-control.ps1 -Mode ContentTrial -EndDate 2026-09-07

# 允许模型调用，并让通过门禁的定时内容自动发布
.\scripts\ops-control.ps1 -Mode ContentTrial -EndDate 2026-09-07 -AllowModel -AutoPublish
```

脚本会显示 PowerShell 确认提示。自动化环境可以显式追加 `-Confirm:$false`；人工操作不建议跳过确认。

## 5. 在线 AI 与 RAG 开关

| Worker 变量           |    当前值 | 作用                                                |
| --------------------- | --------: | --------------------------------------------------- |
| `RUNTIME_MODE`        | `archive` | 公开站处于静态归档模式                              |
| `AI_ENABLED`          |   `false` | 在线生成总开关                                      |
| `RAG_ENABLED`         |   `false` | 在线引用式问答开关                                  |
| `INGESTION_ENABLED`   |   `false` | Worker 在线采集开关；当前采集由 GitHub Actions 承担 |
| `TREND_BRIEF_ENABLED` |   `false` | Worker 在线趋势生成开关；静态周报不依赖它           |

这些值由 `wrangler.jsonc` 管理并随 Worker 部署生效。Cloudflare 控制台可以用于紧急关闭，但后续部署会再次以仓库配置为准。因此正常开启流程应提交配置变更、通过测试并重新部署；在线 RAG 还必须先通过回答引用覆盖和忠实度 Gate。

## 6. 推荐模式

| 场景           |           日报 | 周报 |     在线 AI/RAG | 说明                                          |
| -------------- | -------------: | ---: | --------------: | --------------------------------------------- |
| 长期低成本展示 |           关闭 | 关闭 |            关闭 | 网站继续展示最后快照和历史内容                |
| 面试前内容预热 | 开启至指定日期 | 开启 |            关闭 | 先积累近期内容，费用受模型调用上限保护        |
| 面试演示       |       按需开启 | 开启 | Gate 通过后开启 | 在线能力需要 Turnstile、D1 限流和预算同时正常 |
| 紧急止损       |           关闭 | 关闭 |            关闭 | 先关总开关，再检查 Actions、Worker 日志和费用 |

## 7. 每次变更后的验收

1. 在 GitHub Variables 检查变量是否符合目标模式；
2. 在 GitHub Actions 查看下一次任务是否按计划运行或跳过；
3. 打开 `/api/status`，确认在线 AI/RAG 状态；
4. 打开 `/data/current.json`，确认静态快照仍可访问；
5. 若开启模型，次日检查调用次数、Token、估算费用和质量门结果。
