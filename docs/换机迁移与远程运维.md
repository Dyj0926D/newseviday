# NewsEviday 换机迁移与远程运维

## 1. 结论

NewsEviday 的代码、公开内容快照、工程配置、测试、部署配置和 GitHub Actions 均以 GitHub `main` 分支为版本基准。更换电脑不会中断已经启用的日报、周报、质量监控和 Cloudflare 自动部署。

日常内容更新可以直接通过 GitHub 网页操作。代码优化可以在任意新设备克隆仓库后继续，也可以使用 GitHub 网页编辑器或 Codespaces。Cloudflare Secret、D1 数据和 EdgeOne 项目属于对应云账号，不存放在 Git 仓库中，但不会因为更换电脑而消失。

## 2. GitHub 已保存的内容

| 内容 | 位置 | 是否可在新设备恢复 |
| --- | --- | --- |
| 前端、Worker、Python 管道 | `apps/`、`pipeline/` | 是 |
| 数据契约、主题与来源配置 | `packages/`、`config/` | 是 |
| 当前与历史公开快照 | `apps/web/public/data/` | 是 |
| RAG 与 Eval Harness | `pipeline/eval/`、`pipeline/src/` | 是 |

| 数据库迁移脚本 | `migrations/` | 是 |

| Node 与 Python 依赖版本 | `package-lock.json`、`pipeline/uv.lock` | 是 |

## 3. 不进入公开 GitHub 的内容

以下内容由 `.gitignore` 排除，不能依赖仓库迁移：

- GitHub、Cloudflare、DeepSeek、EdgeOne 的登录会话和两步验证信息；
- `.dev.vars`、`.env` 等本地密钥文件；
- `node_modules/`、Python `.venv/`、构建目录和临时运行 Artifact；
- Codex 本地任务历史、内部项目进度稿和已归档的视觉探索材料；
- Cloudflare D1 中的线上限额、费用和匿名 Trace 数据。

生产所需的 `DEEPSEEK_API_KEY` 已保存在 GitHub Actions Secret；Worker Secret 与 D1 数据保存在 Cloudflare 账号。迁移时不要把真实密钥提交到仓库。

## 5. 新设备恢复步骤

### 5.1 准备账号

确认可以登录以下账号，并保留各自的两步验证或恢复方式：

1. GitHub：仓库、Actions、Variables、Secrets 和 Pull Request；
2. Cloudflare：Worker、D1、Secret、日志和部署；
3. DeepSeek：API Key 与用量查询；
4. EdgeOne：备用站构建与发布。

### 5.2 安装基础环境

- Git；
- Node.js 24.11.0；
- npm 10 或 11；
- Python 3.12；
- uv；
- GitHub CLI；
- 需要本地部署时再使用 Wrangler。

### 5.3 克隆与重建

```powershell
git clone https://github.com/Dyj0926D/newseviday.git
cd newseviday
python -m pip install --user uv
.\scripts\bootstrap.ps1
```

依赖由锁文件重建，不需要复制旧电脑的 `node_modules` 或 `.venv`。

### 5.4 登录与验证

```powershell
gh auth login
gh repo view Dyj0926D/newseviday
.\scripts\ops-control.ps1 -Mode Status
npm run pipeline:doctor
npm run check
```

需要在新设备本地启动 Worker 或执行部署时，再运行：

```powershell
npx wrangler login
npx wrangler whoami
```

本地真实 AI 调试应从 `.dev.vars.example` 复制出未跟踪的 `.dev.vars`，并单独填写密钥。普通前端开发、规则管道和离线 Eval 不需要下载生产密钥。

## 7. 旧设备退出前清单

确认新设备已经完成克隆、依赖重建和账号登录后，再处理旧设备：

1. 检查 `git status`，确认没有未提交的业务代码或公开内容；
2. 不复制 `node_modules`、`.venv`、构建缓存和临时 Artifact；
3. 如需保存内部项目进度稿，使用个人受控存储单独迁移，不上传公开仓库；
4. 退出 GitHub CLI、Wrangler、Codex 及浏览器中的相关云账号；
5. 删除本地 `.dev.vars`、`.env` 和下载过的临时 Artifact；
6. 在 GitHub 与 Cloudflare 的安全页面撤销旧设备会话或不再使用的 Token。

完成新设备验收前，不建议清理旧设备凭据或本地文件。
