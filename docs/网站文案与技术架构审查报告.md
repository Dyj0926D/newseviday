## 1. 产品文案审查

### 1.1 核心问题

原页面同时承担产品展示、开发进度汇报和内部运行说明，导致首页以外的页面出现以下问题：

- “P3 静态产品”“动态 AI 默认关闭”“月度预算 35 元”等信息占据产品首屏，访客先看到项目限制，难以快速理解产品价值。
- “Demo、observe、archive、Eval”等工程术语直接暴露，缺少用户能理解的翻译。
- “情报流、今日情报、情报问答、我的画像、数据状态”等名称口径不统一，部分名称偏内部系统。
- AI 暂停、演示快照和成本控制在多个页面重复出现，干扰主要任务。
- 私有 GitHub、PRD、进度文档和参考项目链接不适合作为公开产品入口。

### 1.2 已采用的命名基准

| 原名称            | 当前名称   | 判断                                 |
| ----------------- | ---------- | ------------------------------------ |
| 情报流 / 今日情报 | 最新情报   | 指向内容本身，时间承诺更克制         |
| 情报问答          | 证据问答   | 直接体现差异化价值                   |
| 我的画像          | 关注偏好   | 降低隐私压力和技术感                 |
| Eval              | 质量评测   | 保留技术含义，同时让非技术访客可理解 |
| 数据状态          | 更新状态   | 对用户最关心的问题给出直接答案       |
| 产品介绍          | 产品与技术 | 准确覆盖页面的双重职责               |
| 文章详情          | 情报详情   | 与产品信息架构一致                   |
| 实时快照          | 最新快照   | 不作无法持续兑现的实时承诺           |

内部代码仍可使用 `profile`、`eval`、`snapshot` 等稳定领域名称；公开 UI 使用上表名称，两者无需强行一致。

### 1.3 页面级修改结果

| 页面       | 修改重点                                                 | 当前表达                                           |
| ---------- | -------------------------------------------------------- | -------------------------------------------------- |
| 最新情报   | 首屏从抽象口号改为任务导向；修正海内外和来源统计         | 说明收录范围、中文整理、筛选和原文回链             |
| 情报详情   | 去除虚构的泛化影响对象；问答入口改为可用跳转             | 展示事实、重要性、相关主题、证据与原文             |
| 证据问答   | 取消反复强调模型关闭和归档模式                           | 能力未开放时仍可选问题、查看语料和理解回答边界     |
| 趋势简报   | 删除硬编码的“产品经理影响”和“下一步观察”                 | 只展示快照中有依据的趋势章节与证据                 |
| 关注偏好   | 将“画像”改为更低压力的用户表达；说明本地保存             | 手动设置始终可用，智能整理为可选能力               |
| 质量评测   | 工程状态翻译成发布结论；隐藏无意义内部 ID                | 公开方法、实测指标、样本限制和未完成项             |
| 更新状态   | 去除面试模式、费用和内部部署术语                         | 公开内容更新时间、贡献来源、可用能力和备用访问说明 |
| 产品与技术 | 首屏改为价值说明；移除阶段、预算、私有仓库与参考项目模块 | 解释产品闭环、技术分层、RAG、评测、成本与安全      |

### 1.4 对外内容原则

后续新增文案按以下规则验收：

1. 首屏先回答“服务谁、解决什么、为什么可信”。
2. 运行限制只在相关交互处说明一次，不在多个页面重复。
3. 目标值、样例值和实测值必须明确区分。
4. “实时、智能、自动、生产级”等词只有达到相应 Gate 后才能使用。
5. 私有仓库、内部进度、月度预算和求职阶段不进入公开产品页面。
6. 外部内容始终保留来源、时间和原文入口；AI 结论不能伪装为原始事实。

## 2. 技术架构审查

### 2.1 架构优点

- Vue 页面读取版本化内容快照，采集和 AI 停止时仍可访问已发布内容。
- Python 处理解析、清洗、规范化、精确去重、主题筛选和快照发布，适合低成本且可复现的 MVP。
- Worker 隔离模型密钥，统一处理请求校验、超时、错误和流式响应。
- TypeScript、JSON Schema 和 Pydantic 共同约束核心数据对象。
- Cloudflare 主站与 EdgeOne Makers 备用站共用静态产物，迁移成本可控。
- 质量评测与数据、模型和检索版本绑定，具备回归和回滚基础。

### 2.2 发现与处理

| 优先级 | 问题                                                         | 风险                             | 本轮处理                                                  |
| ------ | ------------------------------------------------------------ | -------------------------------- | --------------------------------------------------------- |
| P0     | Worker 把文章级 hashing 候选标记为 `chunk_dense`             | 对外架构说明和 Trace 失真        | 改为 `article_dense`；产品页明确生产级分块检索尚未发布    |
| P0     | P6.5 审查时持久限流、并发额度和预算台账尚未接入 `/api/ask`   | 公开后可能被滥用并产生不可控费用 | P7 已用 D1、Turnstile 和预算预留/结算闭环解决             |
| P0     | 返回引用只证明证据被注入，尚未证明回答忠实使用               | 可能出现引用与事实不一致         | 质量评测页明确引用覆盖率待评测；P7/P8 增加人工复核        |
| P1     | “中国大陆”被海外统计逻辑误判                                 | 首页海内外计数错误               | 按区域字段是否包含“中国”判断                              |
| P1     | 快照 `sourceCount` 是成功解析来源数，页面却当作内容覆盖来源  | 公开指标虚高                     | 页面按入选文章的 `sourceId` 计算贡献来源                  |
| P1     | DeepSeek 变更日志依赖 URL fragment，规范化时 fragment 被删除 | 多条更新被错误去重               | 标题适配器显式保留 fragment，并增加单元与真实采集验证     |
| P1     | 关注偏好导入只做浅层校验                                     | 异常文件可写入不合理字段和权重   | 增加长度、数量、Topic ID、权重和日期校验                  |
| P1     | 去重后只保留一个主来源                                       | 同一事件的旁证和来源多样性丢失   | 暂不改动 v1 Schema；后续增加 `alternateEvidence` 或来源簇 |
| P2     | 单页应用缺少基础分享与索引元数据                             | 搜索和链接预览效果弱             | 增加 robots、Open Graph、Twitter Card 和 favicon          |
| P2     | 当前 RAG Trace 只进入运行日志                                | 难以长期比较线上失败类型         | P7 评估写入 D1 的最小匿名 Trace 表                        |

### 2.3 Python 与大模型分工

当前分工合理，继续保持：

| 任务                            | 实现方式                         | 原因                             |
| ------------------------------- | -------------------------------- | -------------------------------- |
| URL 规范化、HTML 清洗、精确去重 | Python 规则                      | 速度快、无 Token、结果可重复     |
| 主题关键词初筛与来源配额        | Python 规则                      | 可解释，适合控制内容分布         |
| 相似去重候选                    | Python 字符特征 / Embedding 候选 | 先用低成本方法缩小复核范围       |
| 跨语言标题、摘要和关键事实      | DeepSeek 批处理                  | 需要语义理解和自然语言生成       |
| 关注方向结构化                  | DeepSeek，可选                   | 处理自由输入，结果必须由用户确认 |
| 证据问答与趋势归纳              | 检索 + DeepSeek                  | 生成前必须绑定已收录证据         |
| 指标计算与发布 Gate             | Python                           | 可复现，不能依赖模型临场判断     |

不建议用大模型替代 URL 去重、字段校验、内容配额、状态判断和指标计算。对于模糊去重，大模型只适合作为极少量边界样本的人工辅助，不能进入每条内容的必经路径。

## 3. P7 开始条件

静态产品已经可以进入 P7。在线证据问答开放前必须完成：

- D1 或 KV 持久单 IP 限流、全站日额度和并发保护；
- 预算预留、结算和硬阈值熔断；
- 请求幂等和失败计费边界；
- 生产语料与人工复核黄金集；
- 引用覆盖率、拒答准确率和线上 p95 Gate；
- 大陆两种网络访问记录；
- 第二台设备迁移演练。

Vectorize 和 BGE-M3 可以继续延后。P7 可先完成安全与额度底座，再决定是否用文章级基线做短时受控烟雾测试。

P7 回写（2026-08-02）：前三项工程保护已完成并通过 D1 migration 与自动化测试；生产语料/RAG 质量 Gate、大陆双网络和第二设备迁移仍按原要求挂起，因此 AI 与 RAG 继续关闭。
