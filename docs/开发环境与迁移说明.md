# NewsEviday 开发环境与迁移说明

本文用于把项目从当前公司设备迁移到个人设备。目标是完整带走个人项目代码和公开 fixture，同时不带走公司数据、公司账号、系统证书、代理配置或本机密钥。

## 1. 可以进入个人 Git 仓库

- 代码、PRD、设计文档和公开参考图；
- `package-lock.json`、`pipeline/uv.lock`；
- `.node-version`、`.nvmrc`、`.python-version`；
- `.env.example`、`.dev.vars.example`；
- 人工构造或确认可公开的测试 fixture；
- GitHub Actions、Cloudflare 和 EdgeOne Makers 配置。

## 2. 不可迁移到 Git

- `.env`、`.env.local`、`.dev.vars`；
- DeepSeek Key、Cloudflare Token、GitHub Token、EdgeOne 凭据；
- 浏览器 Cookie、CLI 登录缓存和 SSH 私钥；
- 公司代理、内部 npm/PyPI 地址、公司证书；
- 公司代码、业务数据、客户信息和内部文档；
- 本地 `node_modules`、`.venv`、构建缓存和日志。

账号认证不随 Git 仓库迁移。新设备应重新登录个人账号，旧设备的个人 Token 在迁移验收后撤销。

## 4. 新设备重建

安装 Git、Node.js 24.11.0、Python 3.12 和个人 GitHub 凭据，然后：

```powershell
git clone https://github.com/Dyj0926D/newseviday.git
cd newseviday
git config user.name "Yunjia DI"
git config user.email "107767129+Dyj0926D@users.noreply.github.com"
npm ci
python -m pip install --user uv
python -m uv sync --project pipeline --frozen
npm run check
npm run pipeline:check
npx playwright install chromium
npm run test:e2e -w @newseviday/web
```

也可运行：

```powershell
.\scripts\bootstrap.ps1
```

## 5. 新设备需要重新创建的文件

| 仓库示例 | 本地文件 | 进入 Git |
|---|---|---|
| `apps/web/.env.example` | `apps/web/.env.local` | 否 |
| 根 `.dev.vars.example` | 根 `.dev.vars` | 否 |
| `pipeline/.env.example` | `pipeline/.env` | 否 |

主站本地 Worker 使用根目录 `wrangler.jsonc`，所以读取根目录 `.dev.vars`。`apps/worker/.dev.vars` 只给独立 API 回滚配置使用。

## 6. 云平台迁移

| 平台 | 仓库中保留 | 新设备操作 |
|---|---|---|
| GitHub | Remote URL、Actions 配置 | 重新登录个人账号 |
| Cloudflare | `wrangler.jsonc`、D1 migration | 重新 OAuth/Token 登录；云端 D1 与 Secret 无需导出 |
| EdgeOne Makers | `edgeone.json` | 重新登录个人腾讯云账号并绑定 GitHub |
| DeepSeek | 变量名称和适配代码 | Key 已在 Cloudflare Secret；轮换时重新设置 |

Cloudflare 中已存在 `DEEPSEEK_API_KEY`、`IP_HASH_SECRET`、`TRACE_HASH_SECRET` 和 `TURNSTILE_SECRET`。远程 D1 `newseviday-guardrails` 与 Turnstile Widget 也属于个人 Cloudflare 账号，不随本地 Git clone 复制。迁移代码不需要导出 Secret；换设备后通过个人 Cloudflare 账号管理。只有更换 Cloudflare 账号或主动轮换密钥时，才在新账号重新创建资源与 Secret。

新设备可用以下只读/无 Secret 值命令确认资源：

```powershell
npx wrangler whoami
npx wrangler d1 list
npx wrangler secret list
```

不要通过聊天、Markdown、压缩包或网盘复制真实 Token。

## 7. 离开当前设备前

1. 运行 `npm run security:scan`；
2. 运行 `git status`，确认需要的改动已推送到个人远程；
3. 用 `git ls-files` 确认没有 `.env`、`.dev.vars`；
4. 检查 Git 历史没有 Key、公司路径和公司信息；
5. 在个人设备完成一次全新 clone 和全量测试；
6. 撤销当前设备使用过的个人 Token 或 OAuth Session；
7. 删除本机 `.env`、`.dev.vars`、CLI 登录状态和浏览器登录状态；
8. 按公司设备政策处理 `D:\workspace\eviday` 本地副本。

删除项目或凭据前必须先确认个人远程仓库可恢复。不要把“迁移”理解为复制整个用户目录或浏览器配置。

## 8. 迁移验收

- 新设备 `npm ci` 和 `uv sync --frozen` 成功；
- `npm run check`、`npm run pipeline:check` 通过；
- 桌面和移动端 E2E 通过；
- `npm run dev` 后 Web、API 和静态快照可访问；
- EdgeOne Makers 能从 Git 仓库重建静态站；
- 新设备不依赖公司账号、公司代理或内部制品源；
- 云端 Secret 可用，但仓库和前端构建产物不包含其值；
- 当前设备个人凭据已撤销或退出。
