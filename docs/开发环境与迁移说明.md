# NewsEviday 开发环境与迁移说明

本文档用于把项目从当前公司设备迁移到个人设备，同时避免带走公司数据、公司账号或本机密钥。

## 1. 迁移原则

- 代码、文档、公开 fixture 和 lockfile 可以进入个人 Git 仓库；
- `.env`、`.dev.vars`、云平台登录状态、浏览器 Cookie 和本机缓存不进入仓库；
- GitHub、Cloudflare、EdgeOne、DeepSeek 均使用个人账号；
- 公司网络代理、证书、内部 npm/PyPI 地址和公司数据不得写入项目；
- 新设备必须能够只依赖 README、lockfile 和示例配置完成重建。

## 2. 当前设备上的 Git 状态

本地仓库已在 `D:\workspace\eviday` 初始化，默认分支为 `main`。当前没有配置 Git 用户名、邮箱、GitHub CLI 或远程地址，因此没有绑定公司身份，也暂未创建首次提交。

在确认个人 GitHub 邮箱后执行：

```powershell
git config user.name "你的个人 GitHub 名称"
git config user.email "你的个人 GitHub 邮箱或 noreply 邮箱"
git remote add origin https://github.com/你的账号/newseviday.git
git add .
git commit -m "chore: initialize NewsEviday engineering scaffold"
git push -u origin main
```

如果个人仓库名称不同，只需要替换 remote URL，不需要修改本地目录。

## 3. 新设备环境

建议安装：

1. Git；
2. Node.js 24.16.0；
3. Python 3.12，或者允许 uv 自动安装；
4. VS Code 与仓库推荐扩展；
5. 个人 GitHub 凭据。

然后执行：

```powershell
git clone https://github.com/你的账号/newseviday.git
cd newseviday
npm ci
python -m pip install --user uv
python -m uv sync --project pipeline --frozen
npm run check
npm run pipeline:check
```

Playwright 浏览器首次单独安装：

```powershell
npx playwright install chromium
npm run test:e2e -w @newseviday/web
```

## 4. 需要重新创建的本地文件

| 示例文件 | 新设备本地文件 | 是否进入 Git |
|---|---|---|
| `apps/web/.env.example` | `apps/web/.env.local` | 否 |
| `apps/worker/.dev.vars.example` | `apps/worker/.dev.vars` | 否 |
| `pipeline/.env.example` | `pipeline/.env` | 否 |

当前阶段不需要任何真实 Key 也可以完成安装、测试和页面浏览。

## 5. 个人云账号清单

| 账号 | 使用阶段 | 迁移方式 |
|---|---|---|
| GitHub | P2/P7 | 个人仓库、Actions、内容快照分支 |
| Cloudflare | P7 | Pages、Worker、Secret、域名或 workers.dev 地址 |
| EdgeOne | P7 | 静态备用站 |
| DeepSeek | P5/P6 | Worker Secret，不进入前端和仓库 |

账号 Token 不通过文件复制到新设备。优先在新设备重新登录或重新生成，再撤销旧设备 Token。

## 6. 离开当前设备前

1. 确认所有工作已推送到个人远程仓库；
2. 运行 `git status`，确认没有未提交产物；
3. 检查 Git 历史不存在 `.env`、API Key 和公司信息；
4. 撤销当前设备使用过的个人访问 Token；
5. 删除本地 `.env`、`.dev.vars` 和云平台登录状态；
6. 按公司设备政策处理 `D:\workspace\eviday` 本地副本；
7. 在个人设备执行一次完整重建和测试。

## 7. 迁移验收

- `npm ci` 成功；
- `python -m uv sync --project pipeline --frozen` 成功；
- `npm run check` 通过；
- `npm run pipeline:check` 通过；
- `npm run test:e2e -w @newseviday/web` 通过；
- `npm run dev` 后 Web 与 `/api/status` 可访问；
- 新设备没有依赖公司账号、代理或内部资源。
