# AI 一周受控试运行

## 目标

验证 DeepSeek V4 Flash 在画像整理、文章结构化增强和引用式问答中的输出稳定性、延迟、费用及安全保护。试运行不追求流量，不自动开放趋势简报。

## 统一安全配置

```text
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_THINKING_ENABLED=false
DEEPSEEK_MAX_RETRIES=0
DAILY_QUESTIONS_PER_IP=2
GLOBAL_DAILY_GENERATIONS=5
SOFT_BUDGET_DAILY_GENERATIONS=3
MAX_CONCURRENT_GENERATIONS=1
MONTHLY_BUDGET_CNY=5
HARD_BUDGET_CNY=10
```

成本估算暂按官方计划峰时价格上限计入：输入 2 元、输出 4 元/百万 Token。实际开放前必须再次核对供应商价格。

## 分阶段开关

| 日期 | 开启能力 | 操作边界 |
| --- | --- | --- |
| 准备日 | 全部关闭 | 部署代码、检查 Secret、测试状态接口 |
| 第 1–2 天 | 画像增强 | 全站每日最多 5 次；人工检查结构化成功率 |
| 第 3 天 | 文章增强 | 单次最多 5 篇；只上传 Artifact，不自动发布 |
| 第 4–6 天 | 受控 RAG | 只运行指定问题集；趋势简报继续关闭 |
| 第 7 天 | 全部关闭 | 导出聚合统计，复盘质量、错误、延迟和费用 |

## 开启顺序

1. 保持 `RAG_ENABLED=false`、`TREND_BRIEF_ENABLED=false`；
2. 将 `RUNTIME_MODE` 改为 `warmup`；
3. 将 `AI_ENABLED` 改为 `true`，先验证画像增强；
4. 每日检查 D1 用量、Worker 错误率和 DeepSeek 余额；
5. 文章增强只通过手动 GitHub Actions 触发，`allow_model=true`、`max_model_calls=5`、`open_pull_request=false`；
6. RAG 只在评测环境运行；线上与离线检索路径对齐前，不向所有访客开放；
7. 任一停止条件触发时，将 `AI_ENABLED=false` 并重新部署。

## 停止条件

- 月累计费用达到 5 元软预算或 10 元硬上限；
- 出现密钥泄漏、额度绕过或同一请求重复计费；
- 错误率超过 10%；
- 画像结构化成功率低于 90%；
- 文章结构化成功率低于 90%；
- 指定无答案问题中少于 4/5 被正确拒答；
- RAG 引用无法打开、引用与回答明显不一致；
- p95 端到端延迟持续超过 20 秒。
