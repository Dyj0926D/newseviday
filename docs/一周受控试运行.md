# AI 一周受控试运行

## 目标

验证 DeepSeek V4 Flash 在文章结构化增强、公共周报候选和引用式问答中的输出稳定性、延迟、费用及安全保护。试运行不追求流量；公共周报采用每周一次、证据约束、人工评审发布，访客在线问答仍不开放。

## 统一安全配置

```text
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_THINKING_ENABLED=false
DEEPSEEK_MAX_RETRIES=0
DAILY_QUESTIONS_PER_IP=2
GLOBAL_DAILY_GENERATIONS=5
SOFT_BUDGET_DAILY_GENERATIONS=3
MAX_CONCURRENT_GENERATIONS=1
MONTHLY_BUDGET_CNY=5
HARD_BUDGET_CNY=10
```

成本估算暂按官方计划峰时价格上限计入：输入 2 元、输出 4 元/百万 Token。实际开放前必须再次核对供应商价格。

## 分阶段开关

| 日期      | 开启能力                 | 操作边界                                                              |
| --------- | ------------------------ | --------------------------------------------------------------------- |
| 准备日    | 全部关闭                 | 部署代码、检查 Secret、测试状态接口                                   |
| 第 1–2 天 | 文章增强                 | 每日最多 3 篇；通过评审 PR 发布，逐篇检查 AI 字段                     |
| 第 3–4 天 | 文章增强                 | 每日最多 5 篇；优先整理高分外文和 Key Signal 候选，仍通过评审 PR 发布 |
| 第 5–6 天 | 文章增强 + 受控 RAG 候选 | 文章最多 5 篇；RAG 只运行指定问题集，趋势简报继续关闭                 |
| 第 7 天   | 全部关闭                 | 导出聚合统计，复盘质量、错误、延迟和费用                              |

## 开启顺序

1. 保持 `RAG_ENABLED=false`、`TREND_BRIEF_ENABLED=false`；
2. 公开站继续保持 `RUNTIME_MODE=archive`，避免访客误触发尚未过 Gate 的在线生成；
3. 在线 `AI_ENABLED` 继续保持 `false`，文章增强由定时工作流生成内容 PR，经审核后发布；
4. 每日检查 D1 用量、Worker 错误率和 DeepSeek 余额；
5. GitHub Actions 每天北京时间 09:17 主调度、11:47 备用调度；已有内容 PR 或当天已有成功刷新时，备用任务在 checkout 和模型调用前退出；当前使用 `max_model_calls=5`；
6. 每日任务采集全部启用来源，按确定性价值分和来源配额筛选；只有总分不低于 0.60、目标主题相关度不低于 0.60、发布日期在 45 天内且证据不少于 120 字的内容可以产生新模型调用；每个来源单次最多新增 3 篇 AI 整理，名额按来源轮转；
7. RAG 先在固定生产快照上运行评测；证据门禁、人工黄金集和回答引用同时通过前，不向所有访客开放；
8. 任一停止条件触发时，将 `DAILY_REFRESH_ENABLED=false`，在线生成保持关闭。

## 停止条件

- 月累计费用达到 5 元软预算或 10 元硬上限；
- 出现密钥泄漏、额度绕过或同一请求重复计费；
- 错误率超过 10%；
- 画像结构化成功率低于 90%；
- 文章结构化成功率低于 90%；
- 指定无答案问题中少于 4/5 被正确拒答；
- RAG 引用无法打开、引用与回答明显不一致；
- p95 端到端延迟持续超过 20 秒。
