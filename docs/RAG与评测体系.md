# RAG 与评测体系

## 当前实现

NewsEviday 的在线问答链路由四个步骤组成：

```text
问题校验 → 文章级候选检索 → 证据组装与阈值判断 → 流式回答和引用
```

Worker 会从已发布内容快照中检索候选文章，按字符特征向量相似度排序。最高分低于阈值时直接返回“证据不足”，不会调用模型。证据满足要求时，系统只把选中的内容放入受边界标记的证据块，并要求模型使用 `[1]` 形式引用来源。

当前实现可以称为“引用式 RAG”，不称为生产级 Agentic RAG。

## Eval Harness

评测管道提供：

- 版本化黄金题数据结构；
- 语料规模、分块覆盖率和缺失文章检查；
- Recall@5、Recall@10、MRR、NDCG@10、Hit@5；
- p50、p95 检索延迟；
- 无答案问题和最低分阈值测试；
- `pass`、`fail`、`observe` 质量 Gate；
- 可替换的 Hashing Baseline 和 OpenAI-compatible Embedding 适配层；
- JSON 评测报告，供网页评测页和 CI 使用。

## 当前演示结果

| 字段 | 当前值 |
| --- | --- |
| 数据集 | `rag-gold-demo-v1` |
| 问题数 | 30，其中可回答 26、无答案 4 |
| 语料 | 6 篇文章、6 个短分块 |
| 检索器 | `hashing-chargram-v1` |
| 评测状态 | `engineering_draft_pending_human_review` |
| Gate | `observe` |

| 指标 | 结果 |
| --- | ---: |
| Recall@5 | 0.9615 |
| Recall@10 | 1.0000 |
| MRR | 0.7577 |
| NDCG@10 | 0.8102 |
| Hit@5 | 1.0000 |
| 无答案识别准确率 | 0.5000 |

这些数字只证明评测程序可以运行。语料规模小、题集未完成人工复核、线上文章级检索与离线分块检索尚未对齐，1ms 本地延迟也不代表生产链路延迟。

## 下一轮正式评测

下一版评测集计划扩展到 40–50 题，并按场景分层：

| 场景 | 目标 |
| --- | --- |
| 单篇事实 | 验证基本召回和引用 |
| 多来源对比 | 验证跨文章证据覆盖 |
| 时序变化 | 验证时间范围和新旧信息区分 |
| 跨语言检索 | 验证中文问题对海外资料的召回 |
| 无答案 | 验证拒答和阈值 |
| 提示注入 | 验证证据中的恶意指令不会改变系统约束 |

生成质量将增加引用覆盖率、引用正确率、事实忠实度、答案相关性和人工抽检，并同时记录 Token、费用和端到端延迟。

## 有限步骤 Agentic RAG 实验

Agentic RAG 只在 `eval-only` 轨道实现，计划增加：

1. 问题路由：单事实、对比、时序、信息不足；
2. 最多两个子问题和两轮检索；
3. 证据缺口检查与提前停止；
4. 每一步记录路由、改写、候选、引用、耗时和费用；
5. 固定步数、Token、时间和成本上限；
6. 与普通 RAG 使用同一数据集比较。

只有当质量提升且 p95 延迟、单次费用和拒答准确率都通过 Gate，才考虑进入公开试用。

## 运行评测

```powershell
python -m uv run --project pipeline newseviday-pipeline eval-rag `
  apps/web/public/data/current.json pipeline/eval/rag-gold-demo-v1.json
```
