## 1. 总体判断

PRD v1.0 的产品定位、用户问题、海内外信息差、可选画像、RAG、评测、成本控制和主备站边界已经形成闭环，可以作为作品集项目的需求基线。

当前主要问题集中在可执行性：

1. 内容管道对大模型的依赖偏重，去重、语言识别、基础分类和排序缺少确定性实现。
2. 功能总量超过普通个人项目 3-4 周的安全范围，需要明确核心版与增强版。
3. 产品介绍页只列了内容，没有形成独立页面需求和验收标准。
4. RAG/Eval 已有指标，但缺少数据健康、跨语言、去重质量和不同生成页面的独立评测。
5. newnews 案例可复用的工程思想很多，但仓库根目录未见明确 LICENSE，不能默认复制代码。

## 2. 缺陷与优化项

### P0：开发前必须解决

| 编号 | 问题 | 影响 | 处理结论 |
|---|---|---|---|
| P0-01 | 去重、分类、筛选全部依赖 AI 的倾向过强 | 成本不可控，结果难复现，批任务失败面扩大 | 改为 Python 确定性管道优先，AI 只处理语言理解和生成 |
| P0-02 | 首版同时包含完整运营台、画像、RAG、Eval、双站和大量来源 | 工期高风险，容易长期停在半成品 | 拆分核心版和增强版，运营配置先用 YAML + GitHub Actions |
| P0-03 | 产品介绍页规格不足 | 面试官无法快速理解产品思路与技术能力 | 增加独立 `/product` 页面、页面结构和验收条件 |
| P0-04 | newnews 仓库未见明确 LICENSE | 直接复制代码存在许可风险 | 只复用架构思想、指标定义和测试方法，代码自行实现 |

### P1：应在 MVP 中修正

| 编号 | 问题 | 影响 | 处理结论 |
|---|---|---|---|
| P1-01 | 去重只有“URL/标题/语义”描述，没有算法与质量指标 | 无法判断重复率是否真实下降 | 增加 URL 规范化、哈希、RapidFuzz、TF-IDF 和 BGE 复核 |
| P1-02 | RAG 评测与趋势简报、摘要质量混在同一套 AI 叙事里 | 指标容易被错误外推 | Q&A、摘要翻译、趋势简报分别设置评测面 |
| P1-03 | 缺少 corpus health gate | 语料陈旧或嵌入缺失时，指标可能失真 | 发布前校验来源新鲜度、分块覆盖和 embedding 覆盖 |
| P1-04 | 静态快照如何同步到两个站点不够具体 | 备用站可能只有外壳，没有数据 | 增加 `content-snapshots` 分支和双站构建约定 |
| P1-05 | 用户画像会发送第三方模型，但提示只覆盖公司机密 | 隐私告知不足 | 增加“输入会发送至模型服务进行处理”的明确确认 |
| P1-06 | 费用估算没有区分原始候选数和实际 AI 处理数 | 来源扩张后成本可能线性上升 | Python 先筛到 30-40 条，再调用 DeepSeek |
| P1-07 | 站点设置完全依赖 `/admin` | 增加认证和后台开发成本 | 核心版使用配置文件与手动工作流，后台放入增强版 |

### P2：上线后优化

| 编号 | 优化项 | 建议 |
|---|---|---|
| P2-01 | 自动根据点击行为调整画像 | 等有真实流量和隐私方案后评估 |
| P2-02 | 在线 hybrid/rerank | 仅在 dense 检索失败集证明必要时启用 |
| P2-03 | Agentic RAG | 先做离线评测，只针对比较、多跳和证据不足问题 |
| P2-04 | GraphRAG | 关系型失败案例达到明确数量后再评估 |
| P2-05 | 个性化趋势简报 | 用户量和模型预算稳定后再做 |

## 3. Python 与大模型能力边界

### 3.1 推荐结论

采用“Python 批处理 + Workers 在线接口 + 模型生成”的混合架构。

Python 处理可确定、可测试和批量执行的任务。大模型处理需要语义理解、跨语言表达和自然语言生成的任务。Embedding 负责跨语言相似度和 RAG，不用生成式大模型做重复判断。

### 3.2 能力分工

| 任务 | 首选实现 | 原因 |
|---|---|---|
| RSS/API 抓取 | Python `httpx` / `feedparser` | 稳定、并发方便、无需模型 |
| HTML 正文提取 | Python `trafilatura`，失败时规则 fallback | 低成本、可测试 |
| URL 规范化 | Python | 完全确定性 |
| 精确重复 | 规范 URL + 内容哈希 | 快速、准确 |
| 同语言近重复 | RapidFuzz + TF-IDF 字符 n-gram | 适合标题改写，成本低 |
| 跨语言或模糊重复 | BGE-M3 embedding 余弦相似度 | 比生成式 LLM 稳定、便宜 |
| 语言识别 | Python 语言检测库 + 来源默认语言 | 无需模型 |
| 时间、来源、实体清洗 | Python | 确定性 |
| 主题规则初筛 | Python 关键词、来源权重、黑白名单 | 可解释 |
| 中文标题与摘要 | DeepSeek V4 Pro | 需要跨语言理解和表达 |
| 模糊分类 | DeepSeek，与摘要同一次调用 | 避免额外请求 |
| 用户画像语义增强 | DeepSeek V4 Pro | 自然语言转结构化画像 |
| RAG 回答 | BGE-M3 + Vectorize + DeepSeek | 检索与生成分工 |
| 7 日趋势简报 | DeepSeek V4 Pro | 需要跨文档归纳 |
| Eval 指标 | Python | 指标计算必须可复现 |
| LLM Judge | DeepSeek，外加人工抽查 | 只用于生成质量评测 |

### 3.3 去重策略

按四级执行：

1. URL 级：移除 tracking 参数、统一协议和尾斜杠，匹配 canonical URL。
2. 内容级：对规范化标题和正文摘要计算 SHA-256。
3. 近重复：RapidFuzz 标题相似度和 TF-IDF 字符 3-5 gram 余弦相似度。
4. 语义级：只对临界样本调用 BGE-M3，对跨语言同一事件进行复核。

建议阈值需要通过标注集校准，不能直接写死为“通用最佳值”。

首版建立 100 对样本：

- 40 对确定重复；
- 40 对确定非重复；
- 20 对跨语言或边界样本。

目标：

| 指标 | 目标 |
|---|---:|
| 重复识别 Precision | ≥ 0.95 |
| 重复识别 Recall | ≥ 0.90 |
| 人工复核比例 | ≤ 10% |
| 发布后重复条目率 | ≤ 5% |

### 3.4 性能判断

每日原始候选量控制在 100 条以内时，Python 批处理足够：

- 网络采集使用异步 I/O，单来源并发受限；
- 先按语言、日期、来源和实体进行 blocking，减少全量两两比较；
- TF-IDF 使用稀疏矩阵；
- BGE 只处理临界样本；
- DeepSeek 只处理筛选后的 30-40 条候选；
- 用户在线问答继续运行在 Cloudflare Worker，不让 Python 批任务承担实时请求。

不建议在 GitHub Actions 中下载和常驻本地 BGE-M3。模型体积、冷启动和缓存不确定性会拖慢任务。沿用 Workers AI 的托管 embedding 更符合当前预算。

## 4. newnews 案例复用评审

参考项目：

- [huiq777/newnews](https://github.com/huiq777/newnews)
- [项目与简历说明](https://github.com/huiq777/newnews/blob/main/docs/project-interview-resume-brief.md)
- [架构说明](https://github.com/huiq777/newnews/blob/main/docs/architecture.md)
- [当前状态](https://github.com/huiq777/newnews/blob/main/docs/current-state.md)

### 4.1 可以复用的设计思想

- chunk-level dense retrieval 作为生产基线；
- article-level retrieval 作为 fallback；
- retriever input、候选、注入上下文和 fallback reason 分层 Trace；
- Recall、MRR、NDCG、Hit 和延迟联合评测；
- corpus health 通过后才信任 Eval；
- rerank、hybrid 和 Agentic RAG 先放在 eval-only；
- 新策略必须通过质量、延迟和 rollback gate；
- Q&A、Deep Analysis 和 Trend Brief 分别评测。

该项目公开结果显示，chunk dense 在延迟与质量间取得较好平衡，而 rerank_hybrid 虽然指标更高，但 p95 延迟不适合直接上线。这种“离线质量上限与在线默认策略分开”的取舍适合 NewsEviday。

### 4.2 NewsEviday 的优化

- 增加中英文和跨语言问题到黄金测试集；
- 增加国内外对比问题；
- 增加产品名、版本号和缩写等 hard negative；
- 每篇文章最多注入两个 chunk，避免单篇文章占满上下文；
- 增加证据冲突标记；
- 增加重复数据评测；
- 将生成式摘要、趋势简报和 Q&A 分成三套质量门槛；
- 默认生产只使用 chunk dense，rerank 与 Agentic RAG 保持离线；
- 记录配置、语料、模型和 Git commit 版本。

### 4.3 许可边界

评审时在仓库根目录未发现明确 LICENSE 文件。

处理原则：

- 可以阅读公开文档和学习架构思路；
- 可以采用通用 RAG/Eval 方法和公开指标定义；
- 不直接复制源代码、Prompt、数据库 migration 和页面素材；
- NewsEviday 自行实现，并在项目介绍页标注“参考案例与改进点”。
