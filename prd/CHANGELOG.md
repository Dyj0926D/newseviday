# NewsEviday PRD 变更日志

本文件记录 PRD 的版本、主要调整、决策原因和影响范围。

## 版本规则

- 主版本：产品定位、核心用户或总体架构发生重大变化，例如 `v1.0 → v2.0`。
- 次版本：新增完整功能模块或明显调整产品范围，例如 `v1.0 → v1.1`。
- 修订版本：修正文案、参数、验收标准或非结构性错误，例如 `v1.0 → v1.0.1`。

每次修改 PRD 时，先更新 `NewsEviday-PRD.md` 的版本与日期，再在本文件顶部追加一条记录。

## v1.1 — 2026-07-31

状态：完成首轮 PRD 评审，作为视觉与技术实施基线。

### 评审结论

- PRD 有条件通过。
- 主要缺陷是 AI 使用边界偏宽、首版范围偏大、产品介绍页规格不足。
- 参考项目 newnews 未见明确 LICENSE，只复用方法和指标框架。

### 架构调整

- 增加 Python 3.12 离线批处理。
- Python 负责采集、正文提取、标准化、分层去重、规则筛选、快照和 Eval。
- RapidFuzz 与 TF-IDF 负责同语言近重复。
- BGE-M3 只复核跨语言或临界重复，并继续用于 RAG embedding。
- DeepSeek 只处理翻译摘要、模糊分类、画像增强、RAG 回答和趋势简报。
- 内容管道先筛到 30-40 条候选，再调用 DeepSeek。
- 增加 `content-snapshots` 分支与双站快照发布约定。

### 产品调整

- 将“关于项目页”升级为独立 `/product` 产品介绍页。
- 产品介绍页同时展示产品思路、核心能力、整体架构、AI 分工、RAG、Eval、成本与安全。
- 核心版运营配置改为 YAML + GitHub Actions 手动工作流。
- 可视化 `/admin` 调整为增强版，控制 MVP 工期。
- 核心版来源数量收敛为 6-8 个。

### RAG 与评测

- 生产默认采用 chunk-level dense retrieval。
- article-level dense retrieval 保留为 fallback。
- 每篇文章最多注入 2 个 chunk。
- 增加 corpus health gate。
- 增加去重 Precision/Recall 和人工复核率。
- 摘要翻译、趋势简报、Q&A 分别评测。
- hybrid、rerank、Agentic RAG 保持 eval-only。

## v1.0 — 2026-07-31

状态：正式需求基线，待视觉设计与开发。

### 新增

- 将正式产品名称确定为 NewsEviday。
- 在 PRD 开头增加完整产品介绍、主要功能和产品亮点。
- 将海内外新闻与技术情报整理确定为核心能力。
- 增加海外原始信息的中文标题、结构化摘要、术语解释和证据保留。
- 增加国内/海外内容比例和信息时效指标。
- 增加 Data Intelligence 一级分类。
- 增加站点主题配置，可以调整 Data Agent、统一语义层、智能数据湖等关注方向。
- 增加可选个人画像和 DeepSeek 语义增强流程。
- 增加画像确认、编辑、导入、导出和清除能力。
- 增加本地标签加权推荐和推荐原因。
- 增加归档、预热、面试三种运行模式。
- 增加内容更新、RAG、简报、画像 AI 和总 AI 开关。
- 增加运营控制台、预算阈值和暂停恢复规则。
- 增加 Cloudflare 主站、EdgeOne 备用静态站的能力边界。
- 增加完整安全、隐私、迁移、上线和验收要求。

### 关键决策

- 默认海外内容占 60%，国内内容占 40%，比例可以调整。
- 站点主题控制每日采集方向，个人画像只调整已发布内容的排序。
- 用户不创建画像时使用通用信息流。
- 个人画像默认保存在浏览器，不建设账号体系。
- MVP 使用标签权重推荐，不训练推荐模型。
- 每位用户不单独采集内容，也不单独生成趋势简报。
- RAG 只检索最近 30 天。
- 默认运行模式为归档模式，模型费用接近零。
