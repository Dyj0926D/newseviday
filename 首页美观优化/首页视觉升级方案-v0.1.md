# NewsEviday 首页视觉升级方案 v0.1

## 1. 设计判断

这是一个面向产品经理、AI 产品经理和招聘方的作品集型情报首页。现有页面已经具备清晰的信息架构和稳定的信息流，适合做局部沉浸式升级。

设计参数：

| 参数 | 建议值 | 说明 |
| --- | ---: | --- |
| DESIGN_VARIANCE | 6/10 | 保留 Linear 式秩序，增加首屏层次 |
| MOTION_INTENSITY | 6/10 | 有明显动态，但不做重度 3D 和滚动劫持 |
| VISUAL_DENSITY | 4/10 | 首屏留白，信息流维持当前密度 |

视觉语言：深紫蓝、克制科幻、信号感、证据感。品牌紫色保留为唯一强调色。

## 2. 当前页面审计

### 2.1 应保留的内容

- 首屏大标题和完整首屏高度。
- `发现变化，看见脉络` 的双四字主标语。
- 关注偏好和产品介绍两个入口。
- 首屏离开视口后，顶部导航压缩。
- 搜索、主题筛选、信号概览、重点情报和连续信息流。
- 360、390、768、1024、1280、1440 六档验收视口。

### 2.2 当前不足

- 首屏主要依赖浅色背景和同心圆，品牌记忆点偏弱。
- 页面缺少能够表达“全球信号汇聚”的动态视觉。
- 首屏与信息流之间只有背景分界，叙事过渡较弱。
- 当前首屏很稳定，但作品集展示时缺少一眼可识别的技术视觉亮点。

### 2.3 改造模式

采用定向演进。只重构首屏视觉层和一次主题过渡，不改业务结构，不推翻现有组件系统。

## 3. 共同设计原则

1. 动效必须表达信息信号、来源连接或用户反馈。
2. 页面只允许一个横向循环带。
3. Logo 只展示真实追踪生态，不表达合作或背书关系。
4. Canvas 和装饰层全部设置 `aria-hidden`，正文保持真实 HTML。
5. 鼠标位置不进入 Vue 响应式状态，避免每帧触发组件重渲染。
6. 移动端不模拟鼠标轨迹，粒子数量降低并关闭高成本效果。
7. 开启 `prefers-reduced-motion` 时，所有无限动画变为静态背景。
8. 首屏离开视口后暂停动画，页面隐藏时停止帧循环。
9. 首屏保持一个主标题、一段说明和两个动作，不增加状态条或装饰文案。

## 4. 方案 A：深空信号场

推荐方案。

### 4.1 视觉描述

- 首屏使用深紫蓝背景，从近黑蓝过渡到品牌紫。
- 60-90 个低亮度粒子形成稀疏星空，少量粒子以细线短暂连接。
- 鼠标附近产生柔和引力偏移和局部亮度变化。
- 点击或停留时产生一次低强度圆形波纹，不保留长轨迹。
- 首屏下方单独设置一条“持续追踪的公开生态”Logo 带，横向缓慢循环。
- Logo 使用 OpenAI、Anthropic、DeepSeek、Qwen、GitHub、Hugging Face、Databricks、dbt Labs 和 arXiv 等当前来源或生态标识。
- 向下滚动时，深色背景经过 160-240px 的紫灰过渡带进入现有浅色信息流。

### 4.2 产品表达

粒子代表分散信号，短暂连线代表证据关联，Logo 带代表来源覆盖。视觉和产品逻辑一致。

### 4.3 技术建议

- 原生 Canvas 2D 绘制粒子和波纹。
- CSS radial-gradient 负责大面积光晕和深浅过渡。
- 本地打包品牌 SVG，不从外部 CDN 加载。
- 使用 `requestAnimationFrame` 驱动 Canvas，不写入 Vue 状态。
- 使用 IntersectionObserver 和 Page Visibility API 控制暂停。

### 4.4 工程量

3-4 个开发日，另加 1 个测试与回归日。

### 4.5 风险

- 粒子过多会影响低端手机帧率。
- Logo 过多容易形成“合作伙伴”误解。
- 深色首屏需要同步处理 Header 对比度和滚动后的浅色状态。

## 5. 方案 B：轨道脉冲

### 5.1 视觉描述

- 延续现有同心圆，将其升级为三条缓慢转动的轨道。
- 轨道上分布少量信号节点，节点按固定节奏发出脉冲。
- 鼠标移动时，离鼠标最近的轨道节点增强亮度并轻微偏移。
- Logo 不做横向轮播，只在轨道边缘以低透明度静态分布。
- 向下滚动时轨道逐渐放大和淡出，露出现有浅色信息流。

### 5.2 产品表达

表达持续追踪、周期更新和多个来源围绕核心主题运行。比星空更接近 Linear 的克制感。

### 5.3 技术建议

SVG 圆环加 CSS transform，鼠标反馈使用 Pointer Events 和 CSS 变量。无需 Canvas。

### 5.4 工程量

2-3 个开发日，另加 1 个测试日。

### 5.5 风险

视觉冲击力低于方案 A，但性能和可维护性最好。

## 6. 方案 C：情报星图

### 6.1 视觉描述

- 首屏展示由来源、主题和证据节点组成的抽象网络。
- 节点位置稳定，连接线按来源与主题关系呈现。
- 鼠标滑过节点时，只显示一个简短名称和关系提示。
- 首屏下滑时，网络节点逐步收束为信息流中的主题筛选项。

### 6.2 产品表达

装饰层直接对应产品信息模型，适合面试时讲数据来源、主题和证据关系。

### 6.3 技术建议

使用固定布局数据和 Canvas 2D。首版不接真实文章图谱，避免引入复杂布局算法。

### 6.4 工程量

4-6 个开发日，另加 1-2 个测试日。

### 6.5 风险

容易看起来像数据可视化产品，可能削弱首页的简洁和大气感。节点标签也会增加移动端重排难度。

## 7. 方案 D：极光聚焦

### 7.1 视觉描述

- 使用两层深紫蓝极光渐变和轻微噪点，不使用粒子网络。
- 鼠标附近形成柔和聚光镜效果，点击时出现一次扩散光环。
- Logo 采用静态单色网格，位于首屏之后。
- 滚动时极光透明度降低，平滑进入现有浅色信息流。

### 7.2 产品表达

品牌感强，科技感适中，重点仍然落在标题和内容入口。

### 7.3 技术建议

主要使用 CSS gradient、mask 和少量 Pointer Events。无需 Canvas。

### 7.4 工程量

1-2 个开发日，另加 0.5-1 个测试日。

### 7.5 风险

实现成本最低，但与常见 AI 网站的极光背景较接近，独特性弱于方案 A 和方案 B。

## 8. 方案对比

| 方案 | 视觉冲击 | 产品语义 | 性能稳定 | 实施成本 | 综合判断 |
| --- | ---: | ---: | ---: | ---: | --- |
| A 深空信号场 | 5 | 4 | 4 | 中 | 推荐，平衡作品集表现与可维护性 |
| B 轨道脉冲 | 4 | 4 | 5 | 中低 | 次选，最符合克制 Linear 风格 |
| C 情报星图 | 5 | 5 | 3 | 高 | 适合后续增强，不建议本轮直接做满 |
| D 极光聚焦 | 3 | 3 | 5 | 低 | 快速改造方案，独特性一般 |

## 9. 对现有工程的影响

### 9.1 预计新增

- `HomeImmersiveHero.vue`
- `SignalParticleField.vue` 或 `OrbitSignalField.vue`
- `TrackedEcosystem.vue`
- 首页专用视觉 Tokens 和静态 Logo 资产
- Canvas 单元测试、减少动态测试和六档视口截图

### 9.2 预计修改

- `HomeView.vue`：替换首页首屏组件，不改数据和筛选逻辑。
- `AppHeader.vue`：首屏内使用深色透明状态，离开首屏后恢复现有浅色紧凑状态。
- `global.css`：增加首页深色 Tokens、过渡层和响应式规则。
- CSP 和构建配置：如果图标全部本地打包，无需新增外部域名。

### 9.3 明确不受影响

- 路由和页面跳转。
- 内容快照和 Python 管道。
- 推荐、筛选和收藏逻辑。
- Worker API、D1、Turnstile、RAG 和 DeepSeek。
- 产品介绍、文章详情、趋势简报等其他页面视觉。

## 10. 性能与验收标准

- 首屏 LCP 目标低于 2.5 秒。
- INP 目标低于 200ms。
- CLS 低于 0.1。
- Canvas 设备像素比上限 1.5。
- 桌面粒子不超过 90，移动端不超过 36。
- 首屏离开视口后动画停止。
- 减少动态模式下无无限动画、无鼠标追踪。
- 360px 和 390px 页面无横向滚动，标题不超过三行。
- Header、按钮和正文达到 WCAG AA 对比度。
- 页面不增加业务接口请求。

## 11. 建议结论

优先选择方案 A“深空信号场”，并吸收方案 B 的轨道线作为低亮度背景元素。不要同时加入可交互节点标签、3D 场景和多条跑马灯。

确认方案后，先生成一张 1440px PC 首页首屏视觉稿和一张 390px 手机稿。视觉稿确认后再开发，预计完整工程量为 4-5 个工作日。
